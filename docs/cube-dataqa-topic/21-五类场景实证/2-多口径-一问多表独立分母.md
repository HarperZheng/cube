## plan 摘录（响应原文）

```
收入金额用严格收入口径（仅收入方向）        → daybook_view.income_amt   （口径词典「收款金额」定案 2026-09-23）
单位按「各单位」词条两口径都出：收入单位     → daybook_view.im_agen_name（口径词典「各单位」定案 2026-09-24）
执收单位口径单独成表对比                  → daybook_view.chg_agen_name（同「各单位」词条）
预算科目用源表自带科目快照（按名称分组）     → daybook_view.sub_name    （口径词典「预算科目×项目」定案 2026-09-27）
占比分母用不带维度的全量收入合计，两表独立   → daybook_view.income_amt  （tables 平等契约）
```

## 口径声明（answer，响应原文）

> 收入金额用 daybook_view.income_amt 严格收入口径（仅收入方向 FIODIRECTION=1）；预算科目用源表自带科目快照 sub_name、项目用 item_name；「各单位」按口径词典 2026-09-24 拍板两口径都出，两张表口径平等、无主次；**占比只在各表内以全量收入合计 30,200,711.05 为分母计算，不跨口径合计**。数据范围：全量历史数据；金额度量已与 Oracle 对数一致。

## 关键点（为什么这个场景重要）

- **预算科目和收费项目分属两张事实表、没有关联路径——不硬拼**，拆成口径平等的表并列交付；
- 每张表自带分母（全量核对一致），**占比只在表内算，不同口径之间绝不加总**；
- 拍板结论已沉淀进口径词典（2026-09-27 定案）——**9-28 同句复跑不再反问，直接按词条出**，
  这就是 PPT 第 8 页「口径词典自动沉淀」机制的实证。
