## 1. 背景与目标

v2 桥（已实施，11-v2 §6.1）有三处"丢过程"点：

1. `_spawn_claude` 用 `--output-format json`（单对象）——五步全工具轮的事件全被丢掉，只剩最终 result
   （chat_server.py `--output-format json` 一行）
2. `proc.stderr` 除报错头 300 字符外整体丢弃
3. claude 自身的完整推理转录写在 `~/.claude/projects/` 内部路径——桥不可见、不可追溯

### 1.1 三层观测定义

| 层 | 内容 | 排查价值 |
|---|---|---|
| **L1 agent 决策层** | 每轮 claude 调了什么工具、传什么参数、工具返回了什么 | 推理链：为什么选这个成员、为什么反问、哪步走偏 |
| **L2 LLM 消息层** | 每轮模型原始输出（文本块 + tool_use + **thinking 块**）、每轮 usage（input/output/cache token） | claude"想了什么"、契约漂移从哪一轮开始 |
| **L3 HTTP 层** | API 请求生命周期（请求行、重试、错误、权限判定） | API 级问题（报错、重试、限流） |

关系：L1 ⊂ L2 ⊂ L3（事件流意义上）。L2 的每条 assistant 消息就是该轮模型原始输出；
每轮完整输入上下文可由流里前面的消息重建（CLAUDE_INSTRUCTION 走 stdin 首条 user 消息，也在流里）。

## 4. 各层内容规格

### 4.1 结果层（qa-log，审计主链路）

| 项 | 规格 |
|---|---|
| 路径 | `logs/qa-log.jsonl`（**自 regress/ 迁移**，历史数据随迁，继续追加） |
| 写入方 | 双写不变（11-v2 §7.5）：answer 主链路由 claude 按 skill 第5步写（`source:"ui"`）；ask/nomatch/error 由桥补 `{outcome, answered:false}` |
| 时间格式 | 统一中国时区 `+08:00` ISO 8601 带偏移（§4.5）；桥已合规（`astimezone()`），claude 侧已知瑕疵（time 偶为 `00:00:00.000Z` UTC 占位，11-v2 §9.3）由 skill 第5步模板修复（§6 #2） |
| 变更点 | 桥 `QA_LOG_PATH` 默认值、CLAUDE_INSTRUCTION 第5条路径、skill 第5步追加命令路径（§6） |

### 4.2 推理层（stream-json 事件流，常开）

spawn 参数（A 方案）：

```
claude -p --output-format stream-json --verbose --max-turns 40
       --permission-mode bypassPermissions --allowedTools "Bash Read Write Edit Grep Glob Skill"
       [--resume <claude_sid>]
```

- prompt 仍走 stdin（中文多行免转义），不变
- `--verbose` 必带：`-p` 下 stream-json 无 verbose 会报 "requires --verbose"（本机 claude 2.1.229 二进制确认）
- **官方格式原样落盘**：stdout 逐行读取，每行一个 JSON 事件，原样追加到 `.jsonl`——
  不重编码、不 pretty-print、不裁剪、无自造渲染（拍板 5）；人类查看配 jq
  （如 `jq -c 'select(.type=="assistant")' 143025_a1.jsonl`）

事件行结构（官方，本机转录与 CHANGELOG 核实）：

| 事件 | 内容 |
|---|---|
| `system`（subtype:init） | `session_id`、`model`、`tools`、`permissionMode` |
| `assistant` | 完整 `message.content`：文本块 + `tool_use`（含完整 input）+ **thinking 推理块**；每条带 usage |
| `user` | `tool_result` 完整内容 |
| `result`（结尾） | `result`、`session_id`、`duration_ms`、`num_turns`、`usage`、`total_cost_usd`、`is_error`、`subtype` |

解析改动（兼容现有逻辑）：`_spawn_claude` 从"单 JSON 解析"改为"**逐行收集 + 取最后一条
`type=="result"` 行**"——result 行是单对象 json 模式的超集，`result`/`session_id` 字段照旧返回；
`subtype:"error_max_turns"`（--max-turns 打满）与 `is_error:true` 照常走失败路径。

超时路径：`subprocess.run(timeout)` 抛 TimeoutExpired 时，已捕获的部分 stdout 仍是合法 JSONL
前缀——**原样落盘** + 扫 init 行取 `session_id` → best-effort 拷 debug 文件；错误照旧抛。
（Windows 下杀 cmd 包装会孤儿化 claude.exe，11-v2 §6.1 已知；debug 文件可能延迟 flush，best-effort 不强求）

### 4.3 L3-lite（--debug 开关，默认关）——**R2 拍板：已下线**

> **下线说明（R2）**：debug.txt 不再需要——§4.6 运维日志的 `[claude]/[agent]` 行以 `+08:00`
> 覆盖 API 请求/重试/时序信息（且实时可 tail）。`CLAUDE_DEBUG_LOG` 开关、spawn `--debug`
> flag、`~/.claude/debug/<sid>.txt` 拷贝逻辑随之下线。以下 R1 规格保留作历史。

| 项 | 规格 |
|---|---|
| 开关 | 环境变量 `CLAUDE_DEBUG_LOG`（默认 `0` 关；`1/true/on` 开） |
| 行为 | 开启时 spawn 追加 `--debug`；spawn 结束后把 `~/.claude/debug/<claude_sid>.txt` 拷贝为 `<HHMMSS>.debug.txt` |
| claude_sid 来源 | 续轮 spawn 前 `_SESSIONS` 已知；首轮/超时从 result/init 行取（§4.2） |
| 内容边界 | API 请求生命周期（`[API REQUEST] /v1/messages`、重试、错误、权限判定）；**不含原始请求/响应体**（无 system prompt、无 body）；auth 只出现环境变量键名不出现值（2.1.2 起脱敏） |
| 登记 | `.env` 追加 `CLAUDE_DEBUG_LOG=0`；host 桥进程以 shell 环境为准（CLAUDE_TIMEOUT 同通道） |

### 4.4 索引（index.jsonl）

每次 spawn 追加一行（桥写，try/except 包裹）：

```json
{"time":"2026-09-24T14:30:25+08:00","attempt":"a1","claude_sid":"<uuid>","resume":false,
 "question_head":"<问题前40字符>","file":"143025_a1.jsonl","outcome":"ok|timeout|error",
 "duration_ms":123456}
```

作用：resume 续轮的事件流只含本轮增量（之前轮次在上轮文件里）；resume 失败重建后 claude_sid
变化——靠 index 把同一 chat 会话的文件串成完整链条。

### 4.5 时间规格（统一中国时区 +08:00，拍板 7）

| 时间源 | 规格 |
|---|---|
| 桥写时间（文件名 `HHMMSS`、index 的 `time`、qa-log 桥侧行） | `datetime.now().astimezone().isoformat()`——host 为中国时区即 `+08:00` 带偏移；无新依赖（不引入 zoneinfo） |
| claude 写 qa-log 的 `time` | skill 第5步模板明确要求 `+08:00` 带偏移——修复 11-v2 §9.3 已知"偶为 `00:00:00.000Z` UTC 占位"瑕疵 |
| stream-json / `--debug` 官方内容内部时间 | **原样不动**（拍板 5 官方格式零重编码）——统一时区规格只约束桥写字段与 skill 模板，不改官方产物 |
| **容器日志**（cubestore/cube server，docker logs，R2） | compose `environment` 加 `TZ=Asia/Shanghai`——Node（cube server）吃 TZ；cubestore（Rust）若硬编码 Utc 则治不了，实施时重启容器冒烟验证，治不了则记录接受 |
| **bridge.log**（R2 §4.6） | 桥写，`+08:00` 毫秒精度（`isoformat(timespec='milliseconds')`） |

### 4.6 运维日志（bridge.log，R2 新增，按日）

| 项 | 规格 |
|---|---|
| 路径 | `logs/bridge-YYYY-MM-DD.log`（按日，桥本地日期切片） |
| 格式 | `<ISO+08:00 毫秒> <LEVEL> [<组件>] <消息>`，如 `2026-09-24T11:38:50.651+08:00 INFO  [bridge] 响应已送 answer 19 行｜总耗时 37.2s`；**内容块（R2.1）**：标题行 `<ts> INFO  [agent] thinking ── N 字符` + 内容逐行 `<ts> INFO  [agent] │ <行>`——每行仍带经典前缀（grep/tail 逐行可用） |
| 组件 | `[bridge]` HTTP 层（收到问题/锁排队/响应已送/日志落盘/error）；`[claude]` spawn 生命周期（spawn pid/exit/超时杀树）；`[agent]` 五步过程（init/thinking/tool_use/tool_result/最终输出/result） |
| 级别 | INFO 常开；失败落 ERROR（超时/spawn 失败/JSON 解析失败/写失败） |
| 时间戳 | 桥逐行打点——Popen 增量读 stdout，每行到达即记 `+08:00`（R1 的 subprocess.run 整体捕获丢逐事件时间，R2 起弃用） |
| 事件摘要 | **R2.1 拍板：全量内容而不是字符数**——thinking/text/tool_result 记全量内容（多行块 `│` 前缀，标题行带字符数；tool_result list 取各 text 块拼接）；tool_use 记工具名 + 完整入参 JSON；thinking_tokens 噪音事件跳过 |
| 与事件流关系 | jsonl 仍是官方格式原样（拍板 5）；bridge.log 只是**打点摘要层**，深挖仍回 jsonl（jq） |
| 附加收益 | `tail -f logs/bridge-*.log` 实时看 claude 五步推进；锁排队行"等待会话锁（前问未完）"解决排队请求隐身 |

## 7. 明确不采纳

| 项 | 理由 |
|---|---|
| L3-full：`OTEL_LOG_RAW_API_BODIES` + OpenTelemetry（原始请求/响应体、system prompt） | 重（需搭 OTel 通路）；对排查问题帮助有限——CLAUDE_INSTRUCTION 走 stdin 本来就在事件流里，只有 claude 内置 system prompt 看不到；拍板 6 定 L3-lite 为界 |
| `--include-partial-messages`（token 级流式 delta） | 落盘场景不需要；属 v3 实时流式方向 |
| `--forward-subagent-text`（子代理文本进事件流） | cube-ask skill 内联执行不走子代理，用不上 |
| 机制 B（拷贝 `~/.claude/projects/d--develop-cube/<sid>.jsonl` 内部转录） | 拍板 6 定 A——B 多轮混文件、依赖内部路径约定；A 是官方接口且每次 spawn 独立成文件 |
| 自造渲染（.md 时间线等） | 拍板 5——官方格式原样，查看用 jq |
| L3-lite（`--debug` + debug.txt 拷贝，R1 已实施） | **R2 拍板下线**——bridge.log 的 `[claude]/[agent]` 行以 `+08:00` 覆盖 API 请求/重试/时序信息且实时可 tail，官方 debug 产物不再需要（§4.3 下线说明） |

## 8. 风险与边界

| 风险 | 对策 |
|---|---|
| 体积增长 | stream-json 数百 KB/问、--debug 数 MB/问；demo 边界先不设自动清理，膨胀后加"保留 N 天" |
| 敏感面 | bypassPermissions + 全量落盘 → Oracle 数据、模型文件内容、CLAUDE_INSTRUCTION 进 logs——本地单用户 dev 边界内（11-v2 §2 同款），**不外发、不提交该目录** |
| 落盘拖慢问答 | 逐行写盘在 spawn 结束后一次完成（stdout 已整体捕获），不在流式路径上；失败隔离不阻塞 |
| 版本 | 本机 claude 2.1.229：已过 2.1.208"管道下 stream-json 截断丢 result"修复、2.1.229"CRLF 输入崩溃"修复——管道消费安全 |
| HHMMSS 同秒冲突 | 同会话 `_LOCK` 全局串行；跨会话不同目录；跨重启同秒概率忽略（dev 边界） |
| qa-log 双写方路径漂移 | 桥（绝对路径拼接）与 skill（相对 `logs/qa-log.jsonl`，cwd=项目根）指向同一文件；实施后回归验证双路落盘 |
