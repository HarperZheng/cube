## 1. P3 数据核实结论（db.js 跨月实测）

源表 UNE_CBILL 家族（原系统内部叫法"电脑票"，消费方用业务语言"开票"）：

| 核实项 | 结论 |
|---|---|
| 月表范围 | UNE_CBILL_202301~202612 共 48 张，**202302~202609 有数（44 个月，合计 32317 行）**；202301 与 202610-12 为空 |
| FID 跨月唯一性 | **32317 = 32317（100% 唯一）** → count_distinct 与行数一致，receipt_count 安全 |
| 干扰表 | UNE_CBILL_2019（年表，0 行）、UNE_CBILL_20250307（日表，8 位）、BACK2/BACK3040、TMP/TEMP/DAY_TMP——正则 `^UNE_CBILL_[0-9]{6}$` 全部排除 |
| **列数不齐（P3 新坑）** | **2025-01~11 为 105 列（多 FTEMPLATEID）、202512 为 106 列（再加 FDONATETYPE）、其余 104 列**——`SELECT t.*` 的 UNION 报 ORA-01789 |
| 日期 | FDATE 零非法（YYYY-MM-DD，2023-02-02~2026-09-18） |
| join 键 | FRGNCODE/FAGENIDCODE 无空值；FAGENIDCODE→agency（FISFINAL=1）、FBILLID→bill_type.FID、FRGNCODE→region.FCODE 全部 100% 匹配 |
| 口径分布 | FSTATE 1正常 31591 / 2作废 726；FBUSTYPE 1常规 25665 / 2电子转纸质 2608 / 3冲销 2149 / 4直缴转开票 1895（无 5/6）；FISINVOICE 全 1；FISINCOME 1收入 27562 / 0非收入 4755 |
| 金额分布 | **FISINCOME=0（直缴转开票等）承载绝大部分金额**（1.22 万亿 vs 收入业务 1880 万）——income_amt 口径小是数据本身如此，非缺陷 |
| 敏感字段 | payer_name 100% 覆盖（→mask）；payer_tel 26615 笔、payer_no（付款人账号）202 笔（→**不建维度，不对外暴露**） |

cbill_item 月表全部 33 列一致（P0 的 `SELECT t.*` 恰好没踩坑；P3 起同样改列交集，机制统一）。

## 2. globals.py 泛化（monthly_tables + monthly_columns）

- `monthly_tables(prefix)`：cbill/cbill_item 共用，前缀作参数；正则 6 位后缀收紧 +
  **按 `后缀月份 <= 当前月` 过滤未来空表**（202610-202612 等不进 UNION，省空扫描；
  历史空月保留，行为稳定）；
- `monthly_columns(prefix)`（P3 新增）：返回所有**有效**月表的**列交集**
  （having count(distinct table_name) = 有效表数），UNION 按列名显式展开替代
  `SELECT t.*`。新月表多出的列自动被排除；少列/改列名编译期报错（fail loud）。

## 3. 实测踩坑与修正

| 坑 | 现象 | 修正 |
|---|---|---|
| UNION 列数不齐 | `SELECT t.*` → ORA-01789 query block has incorrect number of result columns | `monthly_columns()` 列交集显式展开 |
| **11g 标识符 30 字符上限** | `cbill__total_amount_year_to_date` 类别名 → ORA-00972 identifier is too long | 成员名控制在"cube 前缀+成员名 ≤ 30 字符"；to_date 系列用短名 `amt_*_to_date` |
| **单独 mask 不生效** | payer_name 加 `mask: {sql}` 后查询仍显示完整值 | docs/11 语义：脱敏由 access_policy `member_masking` 激活，**且必须与 `member_level` 同一条策略**——`member_level: excludes: [payer_name]` + `member_masking: includes: [payer_name]` → 对所有人脱敏 |
| Jinja 循环变量 | 重构 sql 时漏掉 `{%- set ym = t[-6:] %}`，TO_DATE 拿到 undefined | 循环内提取 ym 的行不可省 |

## 4. schemaVersion 配置方式验证（P3 专项）

- **PyO3 桥接（cube.py）不支持**：`@config('schemaVersion')` 报
  `ConfigurationException: Unknown configuration property: 'schema_version'`
  （桥接对属性名做白名单校验，queryRewrite 等在列，schemaVersion 不在），
  且错误直接**打挂容器**（进程退出）；
- 依据（node_modules 实证）：`optionsValidate.js:91 schemaVersion: Joi.func()`、
  `server.js:376` 传 context、`CompilerApi.js:104` 每次编译求值——server-core 原生
  支持 JS 配置（`loadConfigurationFromFile` 加载 cwd/cube.js），但 Node 侧实现
  需自连 Oracle，未采用；
- **最终决策：兜底方案生效——新月份上线时 `docker compose restart cube`**
  （月表按月新增，重启频率可接受；schemaVersion 待生产需要时再按 JS 配置验证）；
- 教训：Python 配置桥接的属性白名单是硬边界，**新增配置属性先小验证再依赖**。

## 5. 宏 import 实测（P3 专项，docs/12 §5）

- **测通**：`conf/model/macros/ptd.jinja` + cube yml 顶部
  `{%- import 'macros/ptd.jinja' as ptd -%}` + measures 块内
  `{{ ptd.to_date_measures("amt", '{CUBE}."FTOTALAMT"', title='金额累计') }}`
  编译通过，生成 amt_week/month/quarter/year_to_date 四个度量（meta 可见）；
- 相对 docs/12 原文的增强：宏加了可选 `title` 参数（原文生成的度量无中文标题）；
- `{CUBE}."FTOTALAMT"` 作为 Jinja 字符串参数安全（花括号在字符串字面量内不解析）；
- 后续时间口径度量（to_date 系列等"一个度量 × N 周期"形状）用宏批量生成，
  extends 只用于成员定义复用——两者分工见 02 约定第 7 条；
- 宏的作用与参数说明（含直观类比）单独成文：[05-宏说明.md](./05-宏说明.md)。

## 6. cbill cube 建模决策

- 度量：count / receipt_count（countDistinct FID，去重口径）/ total_amount /
  avg_amount / normal_count、void_count（FSTATE）/ income_amt（FISINCOME=1）/
  regular_amt、ebill_paper_amt、offset_amt、direct_transfer_amt（FBUSTYPE）；
- 宏生成：amt_*_to_date（短名避 30 字符上限，title 参数补中文标题）；
- 维度：fid（PK，public:false）、bill_month（从表名提取，time）、bill_date（FDATE→time）、
  state、bus_type、is_income、bill_no、region_code、agency_code、bill_id（FBILLID，
  public:false 技术外键）、payer_name（mask）；
- payer_tel / payer_no **不建维度**——手机号与银行账号，指标体系无此需求，暴露面最小化；
- joins：agency（FAGENIDCODE=agency.FAGENIDCODE）、bill_type（FBILLID=bill_type.id），
  均引物理列（02 约定第 13 条）；
- access_policy：双互补策略 + member_level excludes/member_masking includes
  payer_name（脱敏对所有人生效，与行级权限正交）；
- paybook 同步升级脱敏（payer_name mask + 策略升级），回归 diff 零差异、
  JWT(530100)→30 基准不变。
