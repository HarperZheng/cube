# 可以借鉴的开源实现

## 一、Workbook（分析工作台/查询 notebook）

| 项目                  | License                                           | Stars | 活跃度            | 定位                                                         |
| --------------------- | ------------------------------------------------- | ----- | ----------------- | ------------------------------------------------------------ |
| pinterest/querybook   | Apache-2.0                                        | 2.3k  | 2026-09-16 还在推 | 最接近 Cube "Workbook" 概念：notebook 界面 + 表元数据 + 多引擎查询执行 + 定时任务，Python/React |
| evidence-dev/evidence | MIT                                               | 7.0k  | 每天在更          | "BI as code"：SQL + Markdown 写分析报告，编译成交互式报表站  |
| rilldata/rill         | Apache-2.0                                        | 2.9k  | 每天在更          | "BI for humans and agents"，DuckDB 底座、声明式 dashboard 构建 |
| lightdash/lightdash   | 非标准 license（GitHub 标 NOASSERTION，商用受限） | 6.2k  | 活跃              | dbt 语义层之上的 BI，注意 license 不能直接抄代码             |

**借鉴点：**

- Querybook 是和 Cube Workbook 功能集最像的（cell 式 notebook + 元数据面板 + 查询执行 + 发布），可以参考它的 UI 结构和“notebook → 发布”的数据模型。缺点是它面向大数据多引擎，体量偏重。
- Evidence 的“分析即代码”（Markdown + SQL 定义工作簿）更适合你们已有的 git 化 conf/ 风格，且 MIT 干净。
- 你们的「填入构建器 / 固化到看板」链路和 Rill 的“探索 → 固化 dashboard”思路几乎同构，Rill 值得看它的 explore→dashboard 状态设计。

## 二、Python Analysis（分析代码编辑/运行环境）

| 项目                                                | License    | Stars | 定位                                                         |
| --------------------------------------------------- | ---------- | ----- | ------------------------------------------------------------ |
| jupyterlite/jupyterlite                             | BSD-3      | 4.9k  | 纯浏览器 Python（Pyodide/WASM），零服务端，可嵌入现有前端    |
| duckdb/duckdb-wasm                                  | MIT        | 2.1k  | 浏览器内 OLAP 引擎，配合 Pyodide 做本地数据分析              |
| Kanaries/pygwalker                                  | Apache-2.0 | 16k   | dataframe → 拖拽式 Tableau 风格 UI，有 TS 核心库（Graphic Walker）可直接嵌 React |
| perspective-dev/perspective（原 FINOS/perspective） | Apache-2.0 | 11k   | WASM 数据可视化组件，适合大数据量透视表/图表                 |

**借鉴点 / 推荐架构（贴合你们现状）：**

1. **浏览器内方案（不加服务端）**：Pyodide（JupyterLite 内核）+ duckdb-wasm。流程：前端从你们的 Cube REST 桥拉 JSON → 注入 duckdb-wasm（或 Pyodide 的 duckdb）→ pandas/Python 分析 → PyGWalker 渲染。这正好复用你们 embed demo 的 base64 无状态 session 设计，不需要新起 Python 沙箱服务。
2. **服务端方案（更接近 Cube 商业版做法）**：Cube 的 SQL API 说 Postgres wire protocol——服务端用 pandas + psycopg2/asyncpg 直连 Cube SQL API，就能在 Python 里把 semantic layer 当普通 Postgres 查，这是官方 Python Analysis 的开源等价物。执行环境可以直接挂在你们已有的 chat_server.py 旁边（或用 Jupyter Kernel Gateway 做多会话内核管理）。

## 三、一句话建议

- **Workbook**：不整体引入 Querybook（太重），借鉴其 cell/发布模型，自己写薄前端；分析定义学 Evidence 的 markdown+SQL。
- **Python Analysis**：短期用 Pyodide+duckdb-wasm 浏览器内跑（零运维）；要服务端 pandas 就走 Cube SQL API 的 Postgres 协议直连。
- **图表/透视组件**：PyGWalker（拖拽分析）+ Perspective（大数据量表）都是 Apache-2.0/MIT，可直接嵌入。
