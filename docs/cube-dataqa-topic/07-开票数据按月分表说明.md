# 07 开票数据按月分表说明：cbill 的 sql 如何执行

> 用途一句话：**paybook 的数据在一张物理表里（`sql_table` 直连），cbill 的数据
> 在 48 张按月分表里（`sql` 手写动态 UNION）**——本文说清 cbill 的 sql 逻辑与
> 执行过程。
> 实际文件：[cbill.yml](../../conf/model/cubes/facts_cbill/cbill.yml)、
> [globals.py](../../conf/model/globals.py)。

## 一、为什么 cbill 必须用 `sql` 而不是 `sql_table`

Cube 的硬规则：每个 cube 必须有 `sql` 或 `sqlTable` **之一**（都漏写编译报错，
P1 踩过这个坑）。两者分工：

| | `sql_table` | `sql` |
|---|---|---|
| **写法** | `sql_table: UNE_PAYBOOK`（一个表名） | `sql: \|`（一段原始 SELECT） |
| **适用** | 数据在**一张物理表**，直连即可 | 数据在**多张表/需要加工**（UNION、子查询、LEFT JOIN） |
| **Cube 怎么用** | 把表名拼进查询 | 把整段 SQL 当子查询包裹 |
| **本项目实例** | paybook（UNE_PAYBOOK）、5 个维度 cube | cbill、cbill_item（月表 UNION）、agency（版本链过滤 + 字典翻译） |

- **paybook 单表**：缴款书没有分表（P2 核实，只有 UNE_PAYBOOK 一张表 7255 行），
  直连 `sql_table: UNE_PAYBOOK`；
- **cbill 分表**：开票数据按月分表 `UNE_CBILL_202301~202612`，**不存在一张
  "开票总表"**——跨月查询必须在编译期把月表 UNION ALL 成一张虚拟表。

| 类比 | 对应 |
|---|---|
| 快递地址只写"某小区"（一栋楼） | `sql_table: UNE_PAYBOOK` |
| 快递要"1~48 栋全收，打包一起"（无总楼栋名） | `sql:` 手写 UNION |
| 需先筛选/翻译再当表用（agency 的 FISFINAL=1 + 字典翻译） | 也是 `sql:`（子查询） |

## 二、cbill.yml 的 sql 原文（Jinja 模板）

```yaml
sql: |
  {%- set tables = monthly_tables('UNE_CBILL') %}
  {%- set cols = monthly_columns('UNE_CBILL') %}
  {%- for t in tables %}
  {%- set ym = t[-6:] %}
  SELECT {{ cols | join(', ') | safe }},
         TO_DATE('{{ (ym[:4] ~ '-' ~ ym[4:] ~ '-01') | safe }}', 'YYYY-MM-DD') AS "BILL_MONTH"
  FROM {{ t | safe }}
  {%- if not loop.last %} UNION ALL {% endif %}
  {%- endfor %}
```

四个组成部分：

| 部分 | 作用 |
|---|---|
| `monthly_tables('UNE_CBILL')` | **编译期查库**枚举月表名（globals.py，正则 6 位后缀 + 过滤未来空表） |
| `monthly_columns('UNE_CBILL')` | **编译期查库**取所有有效月表的**列交集**（月表列数不齐 104/105/106，`SELECT t.*` 报 ORA-01789） |
| `for t in tables` + `UNION ALL` | 循环生成每个分支 |
| `TO_DATE(...) AS "BILL_MONTH"` | 从**表名**提取月份拼成月初日期（`substr(t, -6)` → '2023-02-01'），time 维度直接按月分组 |

## 三、SQL 如何执行（四步）

### 第 1 步：编译期——Jinja 展开（Cube 启动/热重载时，跑在 Cube 进程里）

globals.py 的两个函数直连 Oracle 查 `user_tables`/`user_tab_columns`，返回
月表名和列交集；Jinja 渲染后，yaml 里的 sql 变成**一条静态大 SQL**（Cube 对
模板一无所知）：

```sql
SELECT "FID","FRGNCODE",...,"FTOTALAMT", TO_DATE('2023-01-01','YYYY-MM-DD') AS "BILL_MONTH"
FROM UNE_CBILL_202301
UNION ALL
SELECT "FID",...,
       TO_DATE('2023-02-01','YYYY-MM-DD') AS "BILL_MONTH"
FROM UNE_CBILL_202302
UNION ALL ...（共 45 个分支，202301~202609，未来空表已被过滤）
```

### 第 2 步：语义层——Cube 把大 SQL 当一张表（编译查询时）

用户查询（measures/dimensions/filters/timeDimensions）在**外面**再包一层：

```sql
SELECT date_trunc('month', cbill__BILL_MONTH) AS "cbill__bill_month_month",
       count(DISTINCT cbill__FID) AS "cbill__receipt_count"
FROM ( /* ← 第 1 步展开的大 SQL，整体当子查询 */ ) AS cbill
GROUP BY 1
ORDER BY 1
```

这就是"**Cube 的 sql 属性 = 一张虚拟表**"的含义：joins、度量、维度全都定义
在这张虚拟表之上。

### 第 3 步：驱动层——11g 兼容改写（preload.js，查询执行前）

若查询带分页，preload.js 把 `FETCH NEXT n ROWS ONLY`（11g 不支持）改写为
`ROWNUM` 分页。注意 Playground 的 Generated SQL 标签显示的是**改写前**语句
（改写发生在驱动执行层）。

### 第 4 步：Oracle 执行——谓词下推（源库自己做）

外层查询的 WHERE/聚合条件下推进 UNION 各分支，每个分支只扫自己那张月表的
索引/分区，**并非 45 张表全量扫描后再过滤**——这是 Oracle 对 UNION 视图的
常规优化。

### 执行流程图

```
用户查询 receipt_count by bill_month
        │
        ▼
Cube 语义层：包一层 SELECT ... FROM ( 大SQL ) GROUP BY
        │
        ▼
Jinja 已在编译期展开：大 SQL = 45 个月表 UNION ALL（无模板残留）
        │
        ▼
preload.js：11g 分页改写（FETCH NEXT → ROWNUM）
        │
        ▼
Oracle：条件下推进各分支，逐月表扫描，返回结果
```

## 四、关键约束与坑（均已实测）

| 约束 | 说明 |
|---|---|
| **Jinja 插值进 SQL 必加 `safe`** | 默认转义把表名渲染成 JSON 引号形式（"2023"），拼进 TO_DATE 报 ORA-01841 |
| **不能用 `SELECT t.*`** | 月表列数不齐（104/105/106，2025 年加 FTEMPLATEID、202512 加 FDONATETYPE），UNION 列数不一致报 ORA-01789 → 用 `monthly_columns()` 列交集 |
| **正则枚举，不能用 LIKE** | 干扰表：主表/备份 BACK/TMP/TEMP/日表 20250307/年表 2019——`^UNE_CBILL_[0-9]{6}$` 全部排除 |
| **未来空表过滤** | 202610-202612 不进 UNION（空分支纯属扫描浪费）；历史空月保留，行为稳定 |
| **sql 必须返回扁平表（无 GROUP BY）** | Cube 自己做聚合，cube sql 层不能先 GROUP BY（11g 兼容，01-design.md §11） |
| **新月份表无文件变更** | 模型不会自动重编译——**现行方案：新月份上线时 `docker compose restart cube`**（schemaVersion 的 PyO3 桥接不支持，见 04 记录 §4） |
| **11g 标识符 30 字符上限** | 生成的 SQL 别名含 cube 前缀，成员名过长报 ORA-00972 |

## 五、验证方式

- **Generated SQL 标签**（Playground）：看第 1、2 步的展开结果（45 个分支、
  无模板残留、无未来表）；注意它是 preload.js 改写**前**的语句；
- `POST /cubejs-api/v1/sql`：同上，接口形式；
- `docker logs cube`：Jinja/编译错误日志；
- 实测结论：45 张有效月表、无 202610、`SELECT t.*` 已替换为列交集
  （04 记录 §7）。
