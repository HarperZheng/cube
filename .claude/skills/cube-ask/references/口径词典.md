# 口径词典（业务词 → 口径约定）

> **维护规则**（写进 SKILL.md 第1步）：
> - 每次歧义经用户拍板后**立即追加**词条，注明定案时间与背景
> - 只能映射到模型 `meta.ai_context` / 成员 description 已提供的选项，
>   **不能发明成员**
> - 与 ai_context 冲突时以 ai_context 为准，并更新本词条

## 词条格式

```markdown
### <业务词>（适用 cube：<cube名>）
- 约定：<成员 / 过滤条件>
- 备选：<...>（什么情况下用备选）
- 定案：<日期>，<背景一句话>
```

## 已定词条

### 当前（适用 cube：suspicious）

- 约定：`filters: [{member: "suspicious.result", operator: "equals", values: ["0"]}]`
  （处理结果 = 0 可疑中、未解除）
- 备选：pending 口径 `filters: [{member: "suspicious.status", operator: "in", values: ["0","1"]}]`
  （未通知+待说明；或直接用 `suspicious.pending_count`）——用户明确问
  "还没处理完的 / 待处理" 时用备选
- 定案：2026-09-22，实例走查（docs/cube-agent-ask.md §一），
  数据分布依据：FRESULT 0 可疑中=19156 / 1 解除可疑=23（模型注释实测值）

### 最近（适用 cube：suspicious）

- 约定：时间轴用 `suspicious.compiled_date`（编制日期，ai_context 默认）；
  范围长度 = 最近 30 天
- 备选：问"开票以来"用 `bill_date`；问季度/本年时按用户明示范围
- 定案：2026-09-22，用户拍板（30 天 / 90 天 / 本年 / 全部中选 30 天）
- 关联约定：问"最近的可疑票据"时，范围口径默认同"当前"词条（result='0'），
  除非用户说明含已解除

### 可疑票据范围（适用 cube：suspicious，泛化词条）

- 约定：默认仅"可疑中"`result='0'`（同"当前"词条）；全表口径需用户明示
- 定案：2026-09-22，用户拍板（全部记录 / 仅可疑中，选后者）

### 企业（适用 cube：cbill）

- 约定：**暂无过滤口径**——`cbill.payer_type`（FPAYERTYPE 缴款人类型）维度已建
  （2026-09-23 轻扩展，usage_view 同步交付），取值 1/2 **语义待业务确认**；
  业务拍板 1 或 2 谁是"单位"后，企业过滤即
  `filters: [{member: "cbill.payer_type", operator: "equals", values: ["<1或2>"]}]`
- 备选：payer_name contains"单位/企业"**不可行**（脱敏只露末 2 字；且原始值
  contains 命中仅 36/3605，该口径本身也漏）
- 定案：2026-09-23，用户拍板"轻扩展建模 payer_type"；语义证据（均不能定案）：
  本表注释无取值说明、异表 BS_PAYINFO_ERROR 同名字段注释"1 个人 2 单位"
  （跨表取值未必一致，字典陷阱）、缴款人名称形态抽样（202603/202604）无区分度、
  1 占 98.9%（202604 3567/3605）、202609 单一取值 1

### 收款金额（适用 cube：daybook）
- 约定：默认 `daybook.income_amt`（FIMAMT 合计带 FIODIRECTION='1' 过滤，
  严格收入口径，实测 30,200,711.05）；净额 `daybook.net_amt`
  （calculated = income_amt - expense_amt，实测 30,200,511.05）
- 备选：expense_amt 支出方向金额（2 行合计 200）并存；
  全表 FIMAMT 混计（30,200,713.05）不建度量（不推荐）
- 定案：2026-09-23，AskUserQuestion（仅收入方向/全部合计/两口径并存，选两口径并存）

### 收款时间（适用 cube：daybook）
- 约定：时间轴用 `daybook.received_date`（FRECEIVEDDATE 收入日期，严格口径）
- 备选：`daybook.pay_date` 缴款日期并存（问"缴款"时用）
- 定案：2026-09-23，用户指定"收款时间的严格口径（收入日期）"

### 退库标志（适用 cube：backpay）
- 约定：`backpay.is_confirm`（FISCONFIRM 是否确认，1=48 已确认——退付流程
  完成确认，"已退库"口径）与 `backpay.is_send`（FISSEND 是否发送银行，
  1=123——流程中间态）两维度并存，按问数场景选用
- 备选：FISBACK 是否回退（仅 1 行=1，数据形态不支持做标志位，未建维度仅存照）
- 定案：2026-09-23，AskUserQuestion（FISCONFIRM/FISBACK/两个都建，选两建）

### 退库时间（适用 cube：backpay）
- 约定：时间轴默认 `backpay.funds_rec_date`（FFUNDSRECDATE 资金到账日期，
  3 笔空、48 笔已确认全部有值，最接近"退库完成"语义）
- 备选：`backpay.apply_date` 退付申请日期（325/325 全覆盖）并存，
  问"申请了多久/按申请时间"时用
- 定案：2026-09-23，AskUserQuestion（到账/申请/两个时间维度都建，选两建、默认到账）

### 执收单位（适用 cube：daybook_view / daybook）
- 约定：`daybook_view.chg_agen_name`（执收单位名称）/ `chg_agen_code`（编码）——
  区别于收入单位 `im_agen_name`（收款入账侧）
- 定案：2026-09-24，ai_context 唯一口径直接采用（"执收"一词 ai_context
  明确映射 chg_agen_code/chg_agen_name），实测 25 个执收单位有值；
  同日成员面定案（优先 view 前缀）后改写 view 前缀（同实体）

### 收入情况（适用 cube：daybook_view / daybook）
- 约定：按收入类别细分交付——`daybook_view.income_sort_name`
  （101 政府性基金收入 / 102 专项收入 / 103 行政事业性收费收入）×
  金额用 `daybook_view.income_amt`（严格收入口径）
- 备选：`im_type` 收入类型（正常/分成）、`item_name` 项目细分
  （问"什么项目"时用）；只问金额合计则不带维度
- 定案：2026-09-24，用户拍板（金额合计/×收入类别/×项目，选 ×收入类别）；
  同日成员面定案（优先 view 前缀）后改写 view 前缀（同实体）

### 各单位（适用 cube：daybook_view / daybook）
- 约定：**无单独口径，两口径都出**（用户拍板）——收入单位
  `daybook_view.im_agen_name`（收款入账侧）与执收单位
  `daybook_view.chg_agen_name`（执收侧）各出一张分组表对比；
  问句明示"执收"时单独走 chg_agen_name（见"执收单位"词条）
- 备选：单口径直答仅当用户在问句中明示"收入单位/执收单位"
- 定案：2026-09-24，用户拍板（收入单位/执收单位/两口径都出，选两口径都出）；
  依据：2026-06 实测两口径取值不同（4 组仅 1 组相同）

### 核销情况（适用 cube：writeoff_view / usage_view）
- 约定：已核销票据份数 = `writeoff_view.inv_num`（核销单票据明细 sum(FINVNUM)），过滤 `state='2'` 已审验；开具票据份数 = `usage_view.receipt_count`（开票笔数去重，每张票据计1）；比率按单位名称对齐跨 view 计算（无联查 view）
- 备选：分子不分审验状态（去掉 state 过滤）；分母 `total_number` 数量合计(份)（定额票一单多份口径）/ `item_count` 含项目份数
- 定案：2026-09-26，用户 ask 拍板（四选项选推荐项：state=2 × receipt_count）；实测 11 家单位比率>100%（份数 vs 笔数口径现象，非数据错误）

### 预算科目×项目（适用 cube：daybook_view / treasury_view）
- 约定：两口径独立出表、独立算占比（不做跨口径合计）——收入日结口径
  `daybook_view` 单位×`item_name`×`income_amt`（单位按「各单位」词条出
  收入/执收两表）；缴库口径 `treasury_view` 执收单位×`sub_name`×`item_amt`
  （缴库明细金额，非收入口径）
- 备选：单口径直答仅当用户明示只要其一
- 定案：2026-09-27，用户 ask 拍板（仅收入日结/仅缴库/两口径都出，选都出）；
  依据：预算科目只在 treasury_item、收费项目只在 daybook，两事实表无联查路径
  （subject↔item join 未声明）
