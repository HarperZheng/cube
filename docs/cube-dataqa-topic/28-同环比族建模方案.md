> 状态：**修订稿**——2026-10-13 定形（同日命名规约两轮修订：伴生成员内部化、对外回归 over 系命名、新增读法矩阵）。CK 23.3 两层方言补丁落地，带维度同环比全形态实测通过；批 1 待开工。
> 范围：fiscal_treasury / fiscal_collection / fiscal_allocation 三个 cube 及对应交付 view；规约全模型通用，后续新 cube 按此复制。
> 依据：`12-calculations-recipes.md` §4（multiStage 三步法）、`13-query-time-parameters.md`（编译期/查询期边界）、`27-new-cube-ask-sop.md`（S1 算式模板库）、26 号方案（口径声明）。

## 一、要解决的问题与机制

问数出现"2024 和 2025 汇缴笔数金额各自多少、同比差别"这类诉求时，同比差不在 query 协议里（成员引用制、无表达式求值），只能答案层两查询相减。方案：把"与上年同期比 / 与上一周期比"**固化为语义层成员**——query 可引用、构建器可回填、固化看板可存，答案层零计算。

机制 = 度量级 `timeShift`（平移）+ `multiStage`（多阶段），docs/12 §4 三步法：**基础度量 → 平移度量 → 差值度量**。

- 平移量（interval）是**编译期属性**写死 yml；窗口（dateRange）与粒度（granularity）是**查询参数**——平移 1 年的一套成员，按 year/quarter/month 分组分别为年/季/月度同比，"近三月 vs 去年同窗"也通吃；
- timeShift 数组多项、每项钉 `time_dimension`：**查询包含哪条时间维度就沿哪条轴平移**（轴随查询语义，成员不翻倍）；
- 前提已核：引擎 1.7.42 带 Tesseract ✓；REST timeShift 不支持是查询期传参此路不通，恰是固化的原因，与 yml 度量级 timeShift 无关；
- 同查询 filter（如 `enter_status='1'`）自动作用于平移度量，分子分母同期口径天然一致。

### CK 23.3 方言补丁（已落地）

Cube 的 CK 方言按 CK 23.9+ 生成 timeShift SQL，本环境 CK 23.3 需两层改写。文件 `cube-patch/schema-compiler/src/adapter/ClickHouseQuery.js`，docker-compose 同名挂载覆盖（`:ro`，容器内留 `.bak` 原件）：

| 生成点 | CK 23.9+ 原生 | 本环境改写 |
|---|---|---|
| 时间平移 | `addDate(col, INTERVAL 1 YEAR)` | `(col + INTERVAL 1 YEAR)` |
| 对齐 join | `isNotDistinctFrom(a, b)` | `(a) = (b)` |

CK 升级 ≥ 23.9 后删除挂载行即恢复原生。等值 join 下 join 键为 NULL 的行不参与对齐——分组键为 NULL 的行无同期值，按"该组无同期数据"报。

## 三、统一规约（全模型一套）

### 3.1 命名（两层：伴生内部 last 系 / 对外差值率 over 系）

成员名 = 原料度量短名 + 族后缀，中文语义进 title。每个平移量一套"伴生 → 差值 → 增长率"三件套：伴生是差值/增长率的**编译依赖**（multiStage 的 timeShift 为成员级属性，sql 无内联平移语法），降级为内部实现、不进 view；对外成员后缀 = 业务对比类型（over 系），与问法一眼对应。同比 = YoY 与粒度无关（财报惯例：季同比写 YoY），故年/季/月同比同用 `_yoy` 系：

| 平移量 | 伴生 `_x`（内部，不透出） | 差值（对外） | 增长率（对外） |
|---|---|---|---|
| 1 year | `_ly`（last year，去年同期值） | `_yoy_diff`（year over year） | `_yoy_rate`（year over year growth rate） |
| 1 month | `_lm`（last month，上月值） | `_mom_diff`（month over month） | `_mom_rate`（month over month growth rate） |
| 1 quarter | `_lq`（last quarter，上季值） | `_qoq_diff`（quarter over quarter） | `_qoq_rate`（quarter over quarter growth rate） |

算式通式（对照值 = 伴生成员）：差值 = `{原料} - {伴生}`；增长率 = `100.0 * ({原料} - {伴生}) / NULLIF({伴生}, 0)`。伴生命名用 last 系服务公式直觉（`sql: '{amt} - {amt_ly}'`），对外命名用 over 系直接映射业务词。

### 3.2 读法矩阵（问数侧绑定唯一依据）

| 问法 | 成员 | 分组粒度 |
|---|---|---|
| 同比（不带粒度） | `_yoy_diff` / `_yoy_rate` | 随问句粒度 |
| 年同比 | `_yoy_diff` / `_yoy_rate` | year |
| 季度同比 | `_yoy_diff` / `_yoy_rate` | quarter |
| 月同比 | `_yoy_diff` / `_yoy_rate` | month |
| 月环比 | `_mom_diff` / `_mom_rate` | month |
| 季度环比 | `_qoq_diff` / `_qoq_rate` | quarter |

- 默认值：问"环比"不带粒度默认**月环比**；问"同比"粒度跟问句走（"这两年"→year、"近几季"→quarter）；
- 年环比不设独立问法——上一年既是去年同期也是上一期，与年同比同体，按同比 year 粒度处理；
- 防错位：`_mom` 系只配 month 分组、`_lq` 系只配 quarter 分组——平移量与分组粒度不匹配的查询对照错位，禁止。

### 3.3 轴随语义

钉轴依据 = 各 view ai_context **已声明**的时间口径，不是新发明：

| view | 度量 | 钉轴 | 依据 |
|---|---|---|---|
| treasury_view | count / amt | build_date + enter_date 双轴 | 缴库/入库随问句语义 |
| collection_view | amt / count | pay_date | ai_context："时间过滤用 pay_date" |
| collection_view | entered_amt | received_date | ai_context："到账看 received_date" |
| allocation_view | count / im_amt / trans_amt | pay_date | ai_context："时间过滤用 pay_date" |

treasury 双轴与其余单轴不是两种机制——都是轴随语义，treasury 语义天然分两侧故双轴。**clear_date / eff_date / reconcile_date / pay_time 一律不配轴**；allocation 的 trans_date/enter_date 是 _last 属性轴不配（去年同期的"最近一轮"平移无意义）。

### 3.4 成员类型与 view 接缝

- 平移伴生成员 type 沿用原料聚合类型（sum）；差值/增长率成员 `type: number`——计算型，S3 金额→sum 筛选天然不误选，绑定靠 ai_context；
- view includes：**伴生成员（_ly/_lm/_lq）一律不进**（内部实现，勿直接查询）；**差值/增长率成员必进**（绑定主力）；存量 `amt_same_period_ly` 改名后同步从 view 撤出（批 2）；
- 可选：各 view 加 folder「同环比」归拢差值/增长率成员；
- 各 view ai_context 追加统一口径段（模板见 §4.1）；
- pre_aggregations 三家全不动（multiStage 不进预聚合，现算）。

## 四、逐 view 应用清单

### 4.1 批 1：fiscal_treasury（同比三件套 amt + count 差值，双轴）

```yaml
      # ── 同比三件套：与上年同期比；时间轴随查询（build_date=缴库口径，enter_date=已入国库口径）──
      # multiStage 现算不进预聚合（同 bill_count 惯例）；写法同 collection 存量 camelCase
      - name: amt_ly          # 内部伴生：差值/增长率的编译依赖，勿进 view includes
        multiStage: true
        sql: '{amt}'
        type: sum
        timeShift:
          - interval: 1 year
            type: prior
            time_dimension: build_date
          - interval: 1 year
            type: prior
            time_dimension: enter_date
      - name: amt_yoy_diff
        title: 金额同比差值(元)
        multiStage: true
        sql: '{amt} - {amt_ly}'
        type: number
        description: 金额同比差（与上年同期）——引擎已算，粒度随问句（年/季/月分组分别为年/季/月度同比）
      - name: amt_yoy_rate
        title: 金额同比增长率(%)
        multiStage: true
        sql: '100.0 * ({amt} - {amt_ly}) / NULLIF({amt_ly}, 0)'
        type: number
        description: 金额同比增长率=(本期−上年同期)÷上年同期×100——引擎已算；上年同期为 0 或无数据时为 null，报"无法计算/该期无数据"勿按 0
      # count_ly / count_yoy_diff 同构（sql: '{count}'）；count_yoy_rate 待 amt_yoy_rate 实测后照抄（按需）
```

view includes 只加 amt_yoy_diff、amt_yoy_rate、count_yoy_diff（伴生 amt_ly/count_ly 不进）。ai_context 追加段（三 view 通用模板）：

> 同比/环比差值与增长率成员（amt_yoy_diff、amt_yoy_rate 等）：与上年同期/上月/上季的差值或增长率，引擎已算，直接绑定，答案层勿重复计算；同比用 _yoy 系（平移量固定 1 年，粒度随问句——按年/季/月分组分别为年/季/月度同比），月环比用 _mom 系（month 分组），季环比用 _qoq 系（quarter 分组），问"环比"不带粒度默认月环比；_ly/_lm/_lq 伴生列为内部实现，勿直接查询；增长率 = 差值÷上年同期×100，上年同期为 0 或无数据时为 null，报"无法计算/该期无数据"勿按 0；时间轴随问句语义——缴库口径按 build_date，已入国库口径按 enter_date 并带 enter_status='1'；同环比查询单条只用一条时间轴；reconcile_date 无同环比语义。

### 4.2 批 2：fiscal_collection（存量合规化 + 同比族补齐）

1. 存量合规化：`amt_same_period_ly` 改名 `amt_ly`，钉 `time_dimension: pay_date`；**从 view includes 撤出**（伴生不透出，§3.4）；同步 ai_context、词典；
2. 补族：

| 成员 | sql | 轴 |
|---|---|---|
| amt_ly / amt_yoy_diff / amt_yoy_rate(按需) | {amt} / 差值 / 率 | pay_date |
| count_ly / count_yoy_diff | {count} / 差值 | pay_date |
| entered_amt_ly / entered_amt_yoy_diff / entered_amt_yoy_rate(按需) | {entered_amt} / 差值 / 率 | received_date |

number（实物量）不建——跨计量单位混总无意义，同环比同样无意义。ai_context 追加段注明：amt/count 族按 pay_date，到账族按 received_date。

### 4.3 批 3：fiscal_allocation（同比族）

| 成员 | sql | 轴 |
|---|---|---|
| count_ly / count_yoy_diff | {count} / 差值 | pay_date |
| im_amt_ly / im_amt_yoy_diff | {im_amt} / 差值 | pay_date |
| trans_amt_ly / trans_amt_yoy_diff | {trans_amt} / 差值 | pay_date |

ai_context 追加段注明：仅 pay_date 一条轴；trans_date/enter_date（最近一轮）不参与同环比。

### 4.4 批 4：环比族与增长率（按需后补）

- 月环比三件套 `_lm`/`_mom_diff`/`_mom_rate`（interval: 1 month，粒度 month）；季环比三件套 `_lq`/`_qoq_diff`/`_qoq_rate`（interval: 1 quarter，粒度 quarter）；轴跟随族语义（entered_amt 走 received_date，treasury 双轴同同比族）；伴生 `_lm`/`_lq` 照 §3.4 不进 view，diff/rate 进；
- allocation 环比诉求预计少，环比成员命名照规约；
- 增长率算式同构，分母换对应伴生（如月环比 `100.0 * ({amt} - {amt_lm}) / NULLIF({amt_lm}, 0)`）；amt 族同比增长率已提前批 1，其余按需照抄。

## 五、机制注意点

1. multiStage 不进预聚合（现算，数据量小无碍），pre_agg 不动，注释防后人误加；
2. 差值/增长率成员 number 计算型，S3 聚合类型筛选不误选，绑定靠 ai_context；
3. 查询级 filter 随平移走，同期口径自动一致；
4. CK 23.3.15 多 join 限制不涉及（平移在引擎层，不动源表 sql）；
5. timeShift 轴键写 `time_dimension`（docs/12 口径）；外层属性 camelCase 已实证，轴键无在仓先例——批 1 落地若编译报错，同义键 `timeDimension` 兜底；
6. 同环比查询单条只用一条时间轴（双轴成员遇多时间维度查询会平移错位）；
7. 差值成员（`amt_yoy_diff`）与并排形态走同一条对齐 join，批 2 首项实测；若意外不可用，退"同期伴生成员 + 答案层相减"（SOP 本路，兜底仍在）；
8. 伴生成员（`_ly`/`_lm`/`_lq`）是差值/增长率成员的编译依赖（timeShift 为成员级属性，sql 无内联平移语法），必须与对应 diff/rate 成对存在、勿单删，且不进 view includes；
9. 差值/增长率成员引用链深度保持 1（sql 直接引 `{原料}` 与 `{伴生}`，勿链差值成员——嵌套 multiStage 未验证），且勿自带 timeShift：自带会平移整个成员窗口，两个引用一起平移，差恒为 0。

## 八、边界

- 非标对比（"近两周 vs 上两周"）不固化，走 SOP 答案层算式，两路互补；
- 窗口需查询期自选且枚举多时，升级 docs/13 的 switch 维度 + case 度量方案（备用，暂不引入）；
- 不建清单：number（实物量）、total_amt（禁 sum 口径不可加）、clear_date/eff_date/reconcile_date 轴、allocation 的 _last 划转轴；
- 词典可选补"同比/环比"词条（ai_context 为主、词典兜底）。
