## 八、与 Oracle 侧差异与建模注意

1. **行数口径不可直接对账**：une_cbill_high 53,386 行（2019-08 起）远大于生产库 yn0411 的 UNE_CBILL_ITEM 8,284 行——CK 是跨环境汇聚库；fne_paybook_high 1,101 行（2021-12 起）又远小于生产库 UNE_PAYBOOK_ITEM 8,068 行，同步范围/筛选条件待核。**任何 CK vs Oracle 的行数、金额比对都要先对齐口径**。
2. **fne_treasury_transfer_main 本环境 0 行**：结构就绪但无数据，缴库环节分析需回 Oracle（FNE_Treasury_Transfer）或等待同步。
3. **粒度**：fne_paybook_high / fne_paybook_full_high / une_cbill_high / une_paybook_high 均为**明细粒度**（主键 fid = 明细表 FID，主表字段冗余展开，ftotalamt 为主表金额合计、famt 为明细执收金额）；fne_treasury_transfer_main 为主单粒度。
4. **`_last` 后缀**：多轮清分划拨下的"最近一轮"值（fenterdate_last / fistransfer_last / ftransdate_last / ftransno_last）；无后缀列为首轮/原始值。取最终状态一律用 `_last`。
5. **ETL 补充列**：fchgfindeptid、fincomesort*（收入分类：101政府性基金 102专项 103行政事业性收费）、fchgbgtage*/frecbgtage*（预算归类，口径待核）、ftransrec*（划转收款方）、frecrgn*/frecsub*/frecfundsnature*（收入侧维度）、fcomcbill*/fcompbill*（票据关联）、fwriteoffbill*（冲红票关联）、fbillcode/fbillname/frgnname、fcreditcode_top、ftreasuryno、fdatatag——Oracle 源表设计稿中不存在，语义为按命名推断，已标"待核"的建模前需与数据方确认。
6. **拼写原样保留**：ftrnasreconciledate（ftrnas）、freveive（une_paybook_high 资金到账情况）为源端列名，查询时别拼错。
7. **fcustom/ficustom**：仅 une_cbill_high 有 ficustom1~10（明细表 FCUSTOM 改名，i 前缀防撞名）；une_paybook_high 的 30 个 fcustom 无 i 前缀，明细自定义列未单独同步；fcustom 物理顺序与编号不一致（cbill 的 31~37、paybook 的 1~10 为后补列），**按列名引用，勿按位置**。
8. **未同步列**：BLOB 签名列（FSIGNATURE、HANDWRITTENSIGN、FPAYBOOKSIGNATURE_TREASURY、FBILLSIGNATURE_TREASURY）、签名算法/证书/财政签名（FSIGNATUREALGORITHM、FSERIALNUMBER、FFINSIGNATURE 等）、FALTERCODE、FVERSION（une_paybook_high）、Treasury 版扩展列（FRECMODE_TREASURY、FCBILLID_TREASURY 等）均未进 CK；票据签名/验签类需求只能回 Oracle。
9. **类型体系**：日期、编码、状态码全部 String（含 fconfirmtotalamt 这类金额也成了 String），分组/过滤直接可用；排序按字典序，数值比较需先 CAST。金额列统一 Nullable(Decimal(18, 6))，布尔列 Nullable(UInt32)，聚合时注意 null 组（与 [[cube-filtered-measure-null-groups]] 同类问题）。
10. **无约束**：CK 无主外键概念，主子表关联靠 fpid（→主表 FID）逻辑键；去重与 join 时以 fid 为唯一键假设需先用数据验证（尤其汇聚库多环境下 fid 是否全局唯一待核）。
