# 数据源说明

> **定位**：讲数据。配套业务背景见 [26-非税收入收缴业务说明](26-非税收入收缴业务说明.md)（业务篇），两篇前后呼应：业务概念 ↔ 数据落地。

当前项目有两个数据库：Oracle 源表库层 和 ClickHouse 宽表库层。

- Oracle (yn0411schema)：作为核心生产库，存储高度规范化的业务明细数据，支撑高频交易与写入。
- ClickHouse (yunnan0508)：作为 Oracle 的同构同步副本，通过 ETL 将 Oracle 的多张关联表“打平”为宽表，采用 MergeTree 引擎并按日期分区。所有复杂查询与统计分析优先走 ClickHouse，以实现读写分离，保障生产库性能。

## 一、 两库关系与查询策略说明
*   **同构同步副本**：ClickHouse 数据库是 Oracle 业务数据库的同构同步副本，业务数据实时/准实时同步至 ClickHouse。
*   **查询优先 CK**：数据库查询优先使用 ClickHouse，Oracle 作为业务源库及必要场景下的查询兜底。

## 二、 Oracle 源表库（yn0411schema）
Oracle 层主要包含 6 个核心业务模块及其底层明细数据表，是业务的原始数据源。主要包括：

### ① 资金收缴（起点）
这是资金业务的源头，记录每一笔资金的缴纳情况。
| 表名 | 作用 | 关键关联 |
| :--- | :--- | :--- |
| **FNE_PAYBOOK** | **财政缴款书主表**。记录缴款书头信息（如缴款人、总金额），是收缴数据的根节点。 | PK: FPID |
| **FNE_PAYBOOK_ITEM** | **财政缴款书明细表**。记录具体的征收项目、金额明细。 | FK: FPID (1:N) |

### ② 清分划拨（资金流转）
收缴后的资金需要进行归属确认和划转，此环节链路最长。
| 表名 | 作用 | 关键关联 |
| :--- | :--- | :--- |
| **FNE_FUNDDIVIDE** | **资金分解明细表**。核心表，确定资金归属（如中央/地方分成），连接收缴与划拨。 | FK: FPAYBOOKSUBID |
| **FNE_COLLECT_TO_TRANSFER** | **汇总划拨流水表**。将多笔收缴汇总，生成待划拨批次。 | FK: FTRANSNO |
| **FNE_TRANSFER_COLLECT** | **划拨汇总表**。划拨侧的汇总结果，未命中本城表逻辑。 | FK: FPARENTID |
| **FNE_CAPITAL_TRANSFER** | **资金划转主表**。记录实际的资金划转指令和批次信息。 | PK: FTRANSNO |
| **FNE_TRANSFER_BANK_MSG** | **商业银行资金划转表**。记录银行侧的反馈报文与状态。 | FK: FTRANSNO (1:N) |

> **流转逻辑：** 收缴(FNE_PAYBOOK) → 分解(FNE_FUNDDIVIDE) → 汇总(FNE_COLLECT_TO_TRANSFER) → 划转主单(FNE_CAPITAL_TRANSFER) → 银行报文(FNE_TRANSFER_BANK_MSG)。

### ③ 资金缴库（入库）
资金最终进入国库的记录。
| 表名 | 作用 | 关键关联 |
| :--- | :--- | :--- |
| **FNE_TREASURY_TRANSFER** | **资金缴库主表**。记录缴库单头信息。 | PK: FTRANSNO |
| **FNE_TREASURY_TRANSFER_ITEM** | **资金缴库明细表**。记录具体缴入国库的款项明细。 | FK: FPARENTID (1:N) |
| **FNE_TREASURY_TRANSFER_MSG** | **缴库资金划转信息表**。记录缴库过程中的交互报文。 | FK: FTRANSNO (1:N) |

### ④ 开具票据（票据侧）
与资金流并行的票据流，记录电子票据的开具。
| 表名 | 作用 | 关键关联 |
| :--- | :--- | :--- |
| **UNE_CBILL** | **电子票据主表**。记录电票的基本信息（票种、号码）。 | PK: FBILLID |
| **UNE_CBILL_ITEM** | **电子票据明细表**。记录票据对应的具体征收项目明细。 | FK: FPID (1:N) |

### ⑤ 汇缴（非税收入汇缴）
针对特定业务的汇缴处理及收款确认。
| 表名 | 作用 | 关键关联 |
| :--- | :--- | :--- |
| **UNE_PAYBOOK** | **汇缴通知书主表**。关联电子票据，记录汇缴通知信息。 | FK: FCOMCBILLID |
| **UNE_PAYBOOK_ITEM** | **汇缴通知书明细表**。通知书的具体款项明细。 | FK: FPID (1:N) |
| **UNE_PAYBOOK_CONFIRM** | **收款确认表**。记录最终的收款确认状态。 | FK: FPAYCODE |

### ⑥ 冲红、遗失、作废（异常/生命周期终结）
处理票据和库存的异常状态。
| 表名 | 作用 |
| :--- | :--- |
| **UNE_WRITEOFF** | **冲红信息表**。记录票据冲红、红票信息。 |
| **UNE_HBILL / ITEM** | **手工票据表**。记录线下手工开票及其明细（本库无数据）。 |
| **UBE_STOCK_INVALID** | **票据库存作废主表**。记录未使用票据的作废申请。 |
| **UBE_STOCK_INVALID_ITEM** | **票据库存作废明细表**。具体作废的票据明细。 |

### 表之间的整体关系

整个数据库可以概括为一条完整的**资金收缴 → 清分 → 划拨 → 缴库 → 开票/汇缴 → 后续票据处理**业务链。

```text
资金收缴
FNE_PAYBOOK
    │ 1:N FPID
    ▼
FNE_PAYBOOK_ITEM
    │
    ▼
清分划拨
FNE_FUNDDIVIDE
    │
    ├── FNE_COLLECT_TO_TRANSFER
    │          │
    │          ▼
    │    FNE_TRANSFER_COLLECT
    │
    └──────────────► FNE_CAPITAL_TRANSFER
                         │ 1:N FTRANSNO
                         ▼
                  FNE_TRANSFER_BANK_MSG
                         │
                         ▼
                    资金缴库
              FNE_TREASURY_TRANSFER
                         │
                    1:N FPARENTID
                         ▼
              FNE_TREASURY_TRANSFER_ITEM
                         │
                    1:N FTRANSNO
                         ▼
              FNE_TREASURY_TRANSFER_MSG
```

票据侧形成另一条业务链：

```text
开具票据
UNE_CBILL
    │ 1:N FPID
    ▼
UNE_CBILL_ITEM


汇缴
UNE_PAYBOOK
    │ 1:N FPID
    ▼
UNE_PAYBOOK_ITEM
    │
    ▼
UNE_PAYBOOK_CONFIRM
```

同时，票据生命周期还存在后续处理：

```text
UNE_PAYBOOK / UNE_CBILL
        │
        ├──────────► UNE_WRITEOFF
        │              冲红/冲销
        │
        └──────────► UBE_STOCK_INVALID
                       │ 1:N FPID
                       ▼
                 UBE_STOCK_INVALID_ITEM
                       票据作废
```

## 三、 ClickHouse 宽表库层详解（查询加速层）

为了应对海量数据的快速检索，ETL 过程将上述 Oracle 表进行了**物理上的“打平”与“聚合”**，形成了以下 6 张核心宽表。**查询时请直接使用以下表名：**

| CK 宽表名 | 对应 Oracle 源表 | 宽表特点与用途 |
| :--- | :--- | :--- |
| **fne_paybook_high** | FNE_PAYBOOK + ITEM | **资金收缴宽表**。已将主表与明细表 Join，适合直接按项目或缴款人查询收缴详情。 |
| **fne_paybook_full_high** | PAYBOOK + ITEM + 全生命周期状态 | **缴款书全生命周期宽表**。不仅包含收缴信息，还关联了后续的清分、划拨状态，适合追踪一笔钱到底去哪了。 |
| **fne_funddivide_transfer** | FUNDDIVIDE + COLLECT + CAPITAL | **清分划拨宽表**。将复杂的分解、汇总、划转三张表合而为一，极大简化了资金流转链路的查询 SQL。 |
| **fne_treasury_transfer_main** | TREASURY + ITEM + MSG | **资金缴库宽表**。整合了缴库主单、明细与报文，用于快速核对国库入库情况。 |
| **une_cbill_high** | UNE_CBILL + ITEM | **票据宽表**。按开票日期分区，适合大规模票据数据的统计与检索。 |
| **une_paybook_high** | UNE_PAYBOOK + ITEM + CONFIRM | **汇缴宽表**。整合了通知书与收款确认信息，方便核对汇缴业务的完成情况。 |

## 四、 核心关联键字典

在进行跨表分析或数据校验时，请重点关注以下字段：

*   **FPID**：**全局最强关联键**。贯穿缴款书、票据、明细表，是连接“资金”与“票据”的核心纽带。
*   **FTRANSNO**：**资金交易流水号**。在清分、划拨、银行报文、缴库环节中传递，用于追踪资金的实际物理流动。
*   **FPAYCODE**：**汇缴业务码**。主要用于汇缴通知书与收款确认之间的匹配。
*   **FCOMCBILLID**：**票据组合 ID**。用于将汇缴通知书与原始的电子票据（CBILL）关联起来。
