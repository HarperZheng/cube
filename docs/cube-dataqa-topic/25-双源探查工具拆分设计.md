## 2. 结构：自包含、不抽公共层、不留兼容入口

- **`agent/oracle.js`** ＝ 现 db.js 原样改名（只动头部注释与 usage 文案）
- **`agent/clickhouse.js`** ＝ 新文件；`new ClickHouseDriver({ dataSource: 'ck_yunnan0508' })`
  自动读 `.env` 的 `CUBEJS_DS_CK_YUNNAN0508_*`——**连接配置零复制**，与 Cube 本体同源
- 文件名全小写 `clickhouse.js`（不用 `clickHouse.js`）：与 oracle.js 对称，
  避开 Windows 大小写不敏感 + git 大小写敏感的组合坑
- **不抽公共层的根因**：oracle.js 的 `q()` 统一转大写＋双引号；CK 标识符大小写敏感，
  必须原样＋反引号（`billId` ≠ `BILLID`）；聚合函数族也不同（`count(distinct)` vs
  `uniqExact`）。硬抽象＝漏方言的 leaky abstraction。各自 ~200 行自包含可读，
  第三个数据源出现时再议
- **db.js 直接删除**：活引用面仅 3 处（§5 一并改），留兼容入口＝双维护

## 3. 命令面（同构九命令，方言内化）

| 命令 | oracle.js（现状不动） | clickhouse.js（方言化点） |
|---|---|---|
| tables | user_tables＋表注释 | `system.tables`（name/engine/total_rows） |
| cols | user_tab_columns＋user_col_comments | `system.columns`＋注释补齐（§3.1） |
| find | 列名/注释 like | `system.columns` 名称＋`table_columns_oracle.COMMENTS` ilike（中文搜字段靠元数据表） |
| count | `count(*)` | `count()` |
| sql / sql -f | 原样进 driver | 原样进 driver（CK 方言；-f 文件态纪律跨源沿用） |
| dist | group by＋sum(case) | group by＋`countIf`；String 日期列 min/max 字典序＝时间序，直接可用 |
| matchkey | not exists 模板（matchStats） | left join＋is null（同思路方言重写） |
| grain | count(distinct) | `uniqExact` |
| fam | like＋union all 逐表实数 | `system.tables.total_rows` 一条查完（元数据秒回不扫表） |

### 3.1 CK 注释补齐（cols/find 的命门）

CK 本体无列注释，ETL 把 Oracle 注释同步进了元数据表（2026-09-29 实测）：

- `table_columns_oracle`：`TABLE_NAME/COLUMN_NAME/DATA_TYPE/COMMENTS/COLUMN_ID`
  （键全大写），FNE_PAYBOOK 47 列中 45 列有中文注释——**find 的中文搜索全靠它**
- `table_columns_clickhouse`：覆盖 CK 表但 COMMENTS 全空（优先读、空则回落）
- `fne_paybook_full_high`：system.columns 实测 129 列、自带 comment 全空

补齐规则：cols/find 输出注释时 `table_columns_clickhouse.COMMENTS` 优先，空则按
**小写列名**对齐 `table_columns_oracle`（宽表列名多为源列小写化，如
`faccagencode` → 捞回源表注释）；ETL 发明列（无同名源列）注释为空属预期。
