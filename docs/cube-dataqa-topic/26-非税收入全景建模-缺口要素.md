# 非税收入全景建模——缺口要素 Oracle 核对

> 状态：**核实结论**——2026-10-09 对照 [26-非税收入数据库表设计(oracle)](26-非税收入数据库表设计(oracle).md) 逐列核对，回填 [26-非税收入全景建模初步设计](26-非税收入全景建模初步设计.md) §9.2 核实项 6（部分核实项 2）；未写任何模型代码
> 范围：初步设计 §二"场景图 ↔ CK 列映射"中的缺口要素（❌ 缺口 / ❌ 完全缺口 / ❌ 名称缺口 / ❌ Blocked / ⚠️ 衍生），逐项核对其在 Oracle 侧是否存在

---

## 一、核对总结论

**不是都有——缺口列大部分集中在 Oracle 缴库侧（FNE_Treasury_Transfer 系），CK 侧缺是因为 ftm 0 行 + ETL 没同步；真正 Oracle 也无的只有 4 类。**

| 核对结果 | 缺口要素 |
|---|---|
| ✅ Oracle 有（7 项） | 收入单位名称、分成方式、是否分成、分成比例、缴库批次、收款银行开户行行号、非税级次（+ 到账金额有支撑列） |
| ❌ Oracle 也无（真缺口，4 类） | 主管部门/归口业务处室名称、（fdt 侧）执收区划名称、收入类型（正常/下级分入/上级分入）、各级区划 parent/level |
| ⚠️ 部分（1 项） | 执收银行名称——缴款书/清分表无名称对，仅缴库单侧有付款银行名称 |

## 二、Oracle 有（表.列）

| 缺口要素 | Oracle 表.列 | 备注 |
|---|---|---|
| **收入单位名称** | `FNE_Treasury_Transfer.frecagenname`（分入单位名称，200） | 仅缴库单有；FNE_FundDivide / FNE_Transfer_Collect / FNE_Capital_Transfer 均只有 `frecagenidcode` 无名称 |
| **分成方式 / 是否分成** | `FNE_FundDivide.fcalcsource`（分解来源：1不分成 2分成 3提留 4余额） | 就在核实项 6 指定的 FNE_FUNDDIVIDE 里，**有** |
| **分成比例** | `FNE_Treasury_Trans_Item.fsharerate`（分成比例串，35） | 不在 FNE_FundDivide；且注释写明仅 Tips 缴金库时提供 |
| **缴库批次** | `FNE_Treasury_Transfer.fmsgbatchno`（缴库批次号，用于凭证缴库）；`FNE_Treasury_Transfer_Msg.fmsgbatchno`（商业银行缴库单号） | |
| **收款银行开户行行号** | `FNE_Treasury_Transfer.fpaybankopenno`（付款行开户行行号）/ `frecbankno`（收款行行号）/ `frecbankopenname`（收款开户行名称）；`FNE_Capital_Transfer.fpaybankno` / `frecbankno` | 划转+缴库两侧都有行号 |
| **非税级次** | `FNE_Treasury_Transfer.fsublevel` / `fsublevelname`；`FNE_Treasury_Trans_Item` 同名两列 | 与设计文档"CK 仅 ftm"一致——源头就在缴库表 |
| **到账金额（衍生）** | `FNE_FundDivide.fispayenter`（是否缴款到账 0/1，20211124 扩展）+ `fpayenterdate`（缴款到账日期）+ `fimamt`（分入金额） | 核实项 2 的口径有了着落：`fimamt where fispayenter=1` |

## 三、Oracle 也无（真缺口）

| 缺口要素 | 核对结果 |
|---|---|
| **主管部门名称、归口业务处室编码/名称** | 全库无对应列。设计文档候选 `ftranobus` 在 Oracle 中是 **FNE_PAYBOOK.ftranobus = 确认交易流水号**（50），不是处室——该候选不成立，应从映射表移除 |
| **（fdt 侧）执收区划名称** | FNE_FundDivide 只有 `fchgrgncode`；连 FNE_PAYBOOK 也没有 `fchgrgnname`——CK 宽表的 `fchgrgnname` 是 ETL 补充列，源头 Oracle 无 |
| **执收银行名称** | FNE_PAYBOOK / FNE_FundDivide 的 `fbankcode` 无名称对；`fbankname`（付款银行名称）/`fpaybankopenname` 只在缴库单侧 |
| **收入类型（正常/下级分入/上级分入）** | 无现成列：`fcalcsource` 是分解来源、`fdatatype` 是正常/冲销确认，都不是收入来源——衍生口径（frecrgn vs fchgrgn + 层级）仍需业务确认 |
| **各级区划 parent/level** | Oracle 设计文档不含区划维表，无从核实，仍需查库（核实项 7） |

---

## 四、对核实项 6 的直接回答

"分成四要素在 Oracle FNE_FUNDDIVIDE 是否存在" → **FNE_FundDivide 只有 `fcalcsource`（分成方式/是否分成）；分成比例、非税级次不在该表，在缴库明细 FNE_Treasury_Trans_Item**。

---

## 五、整体规律

**缺口列的 Oracle 源头几乎都在缴库/划转侧（FNE_Treasury_Transfer 系 + FNE_Capital_Transfer）**，与"CK ftm 0 行、ETL 未同步这些列"互为印证——即这些要素**不是系统没有，是 CK 宽表没带到**。

- 核实项 6（分成要素）→ 定性为 **部分存在**：FNE_FundDivide 有 `fcalcsource`；分成比例/非税级次在缴库明细表
- 核实项 7（ETL 最小集）→ 除原三项（region 层级、收入单位名称、主管部门名称）外，**收入单位名称的源头在缴库单**（`FNE_Treasury_Transfer.frecagenname`），ETL 可从该表补
- Blocked 项（非税级次）→ 维持 Blocked：源头在缴库表，ftm 0 行时 CK 侧仍无数据
- 名称缺口中的 `ftranobus` 候选 → **作废**（实为确认交易流水号）
