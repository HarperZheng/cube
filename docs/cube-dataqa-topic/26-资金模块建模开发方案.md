## 三、鉴权策略（access control 总纲）

### 3.1 JWT（全局登录凭证）参数格式

- **传递方式**：JWT 放 `Authorization: <JWT>` 请求头，Cube 用行业标准 JWKS 验证并解码，得到安全上下文声明（securityContext）用于评估 access_policy（docs/11 认证页）。**payload 必须是对象**，否则报错 `Cannot create proxy with a non-object as target or handler`（docs/11 实测注）。
- **claims 约定**（本项目三条款的判定载体，新 cube 一律沿用）：

| claim | 用户类型 | 值 | 作用 |
|---|---|---|---|
| `region_code` | 财政用户 | 收入区划编码（如 `530000`） | ①条款 if 条件 + `rec_rgn_code` equals 注入 |
| `agency_code` | 单位用户 | 执收单位编码 | ②条款 if 条件 + `chg_agency_code` equals 注入 |
| （双无） | 平台/管理用户 | — | ③条款 `allow_all` 全量 |
| `groups`（可选） | 组细分 | 数组，默认 `['default']` | 组来源（context_to_groups）；按组细分策略是扩展项 |

- **占位符语法**：access_policy 里引用 securityContext 一律 `{ securityContext.region_code }` 花括号占位（conditions 的 if 与 row_level 的 values 同式）；row_level 的 values 可同时引用多个属性（IN 多属性，docs/11 #7），区划层级上卷时的现成路径。
- **与 apiSecret 的分工**：`CUBEJS_API_SECRET` 管认证准入（REST 准入），JWT claims 管授权（行级过滤），两者正交。dev apiSecret 不带 claims → securityContext 双无 → 命中 ③ 全量分支——桥现状即此（chat_server.py 未注入 claims，实测零命中），生产路径由桥/前端注入后再验证三态。
- **测试方法**：Developer Playground 设置自定义 JWT，或 `jwt.sign({ region_code: '530000' }, secret)` 生成测试 token 放入 `Authorization` 头（docs/11）。

### 3.2 access_policy 要素说明

五要素逐个概括；骨架三条款三 cube 通用，**完整 YAML 留 §五/§六/§七 作落地蓝本**，各 cube 只写差异点。

| 要素 | 语义 | 要点 |
|---|---|---|
| `group` | 策略挂载的组 | 现状 `"*"` 全挂；组来源 = JWT `groups`（默认 `['default']`）；按组细分策略是扩展项 |
| `conditions` | 策略生效条件 | if 条件**全部为 true** 才生效；conditions 之间本就是 AND 组合（docs/11:149）；三条款靠 conditions 表达完备覆盖（region 有 / agency 有 / 双无） |
| `member_level` | 成员可见性 | `excludes` 挡成员；view 层 excludes 不影响 JWT 行级过滤——注入在 cube 层（01-cube-agent-ask-demo 现成） |
| `member_masking` | 成员脱敏 | `includes` 脱敏；**必须与 member_level excludes 同条策略**（P3 实测，单独 mask 不生效）；只 collection 有（fdt 无缴款人字段） |
| `row_level` | 行级过滤 | `filters` 三段式（**member 必须是已注册成员**，不含则 JWT 查询永不命中——cbill P6 实测）/ `allow_all: true` 两种形态；values 引 §3.1 占位符；条款可嵌套 `and:`/`or:`（官方现成，框架版本待实测，见下表 #1） |

**白名单制硬语义**：声明了任何 access_policy，未命中任何策略的用户整表拒绝（WHERE 1=0）——所以条款必须逻辑完备覆盖：财政（region）/单位（agency）/平台（双无）。

**AND 与 OR 语义**（开放项集中，验证结论回填此表）：

| # | 语义 | 现状与兜底 |
|---|---|---|
| 1 | row_level 多 filter 默认 **AND**；**OR 官方语法现成** | ✅ 2026-10-10 实测：嵌套 `or:` 支持——allocation ① 条款改双区划 OR 后生成 SQL `(fchgrgncode = ?) OR (frecrgncode = ?)`（写法①落地）；**多策略之间 row filter = 并集（OR）**——docs/11"filters 间 AND"是单策略内多 filter，跨策略是 OR |
| 2 | allocation 双区划 OR | ✅ 2026-10-10 落地：allocation ① 条款嵌套 `or:`（`chg_rgn_code=本 OR rec_rgn_code=本`，fiscal_allocation.yml 现款）——000000 中央 31 行仍 equals 不命中（#4 数据支撑） |
| 3 | JWT 同时带 region+agency | ✅ 2026-10-10 实测 = **OR（并集）**：两策略都命中行过滤取并集（`((A OR B)) OR C`），非 AND——AND 语义需单策略嵌套 `and:`（docs/11 示例三；场景 14 如需 AND 用此改写，v1 不需要） |
| 4 | 省本级 equals 不命中 | `rec_rgn_code` 空值行=未清分行（丢行符合预期）；**000000 中央 31 行**对 530000 省本级用户 equals 不命中——OR 开放项的数据支撑（初步设计 §9.2 #16） |

## 五、fiscal_collection cube（缴款全景，fpf）

明细粒度 = 缴款书×项目行（`fpaybooksubid`）；缴收分侧：无前缀 = 缴款票面、`rec_*` = 收入归属（初步设计 §4.3）；归一化 = sql 虚拟表 LEFT JOIN 预聚合（初步设计 §4.4，全量别名拼接，**窗口函数方案已废弃**——CK 23.3 实测 NOT_AN_AGGREGATE）。

```yaml
# 财政缴款全景事实（fne_paybook_full_high，1,272 行/129 列）—— 非税收入全景 P7 建模
# docs/cube-dataqa-topic/26-非税收入全景建模初步设计.md §三 / 26-资金模块建模开发方案 §五
# 缴收分侧：无前缀=缴款票面、rec_*=收入归属（§4.3）；码名对：code 分组 + name 展示（§4.2）
# 口径：到账金额按 freceiveddate 衍生（fisenter='1' 实测不可用）；ftotalamt 禁 sum（fan trap）
# ⚠️ CK 23.3.15 限制（2026-10-10 实测）：派生表同层 2 个及以上子查询 LEFT JOIN 时，
#    外层查询无法解析星号展开列（UNKNOWN_IDENTIFIER）；归一化分 5 层嵌套、每层仅 1 个 join。
cubes:
  - name: fiscal_collection
    title: 财政缴款全景
    description: |
      缴款全景事实 fne_paybook_full_high，明细粒度缴款书×项目行。
      覆盖缴款+代收+收入归属+划拨状态(_last)；场景 1/2/4/5/6/7/8/12（§3.3.1）。
      消费方统一从 fiscal_collection_view 查；cube 层只留原料。
    public: true

    sql: |
      SELECT * FROM (
        SELECT * FROM (
          SELECT * FROM (
            SELECT * FROM (
              SELECT t.*, c.chg_agency_name_canon FROM fne_paybook_full_high t
              LEFT JOIN (SELECT fchgagencode,
                                arrayStringConcat(arraySort(groupUniqArray(fchgagenname)), ' / ') AS chg_agency_name_canon
                         FROM fne_paybook_full_high GROUP BY fchgagencode) c ON t.fchgagencode = c.fchgagencode
            ) x1
            LEFT JOIN (SELECT frecrgncode,
                              arrayStringConcat(arraySort(groupUniqArray(frecrgnname)), ' / ') AS rec_rgn_name_canon
                       FROM fne_paybook_full_high WHERE frecrgncode != '' GROUP BY frecrgncode) r ON x1.frecrgncode = r.frecrgncode
          ) x2
          LEFT JOIN (SELECT fitemcode,
                            arrayStringConcat(arraySort(groupUniqArray(fitemname)), ' / ') AS item_name_canon
                     FROM fne_paybook_full_high WHERE fitemcode != '' GROUP BY fitemcode) i ON x2.fitemcode = i.fitemcode
        ) x3
        LEFT JOIN (SELECT fsubcode,
                          arrayStringConcat(arraySort(groupUniqArray(fsubname)), ' / ') AS sub_name_canon
                   FROM fne_paybook_full_high WHERE fsubcode != '' GROUP BY fsubcode) s ON x3.fsubcode = s.fsubcode
      ) x4
      LEFT JOIN (SELECT frecsubcode,
                        arrayStringConcat(arraySort(groupUniqArray(frecsubname)), ' / ') AS rec_sub_name_canon
                 FROM fne_paybook_full_high WHERE frecsubcode != '' GROUP BY frecsubcode) rs ON x4.frecsubcode = rs.frecsubcode

    measures:
      - name: count
        title: 缴款明细行数
        drill_members: [pay_date, chg_agency_name, rec_sub_name, item_name, payer_name]
        type: count
      - name: amt
        title: 缴款金额(元)
        description: famt 合计——缴款明细口径
        drill_members: [pay_date, chg_agency_name, item_name]
        sql: "{CUBE}.`famt`"
        type: sum
      - name: entered_amt
        title: 到账金额(元)
        description: sum(fimamt) WHERE freceiveddate 非空——2026-10-09 口径（fisenter='1' 实测不可用：'1'仅1行/空×1234）；完整判定=三条件（fisenter+fenterdate+ftrnasreconciledate），v1 按单条件
        sql: "{CUBE}.`fimamt`"
        type: sum
        filters:
          - sql: "{CUBE}.`freceiveddate` != ''"
      - name: total_amt
        title: 票面金额(元)
        description: 整票金额复印在每明细行（fan trap）——仅供明细下钻，禁 sum，max=该组最大票面金额
        sql: "{CUBE}.`ftotalamt`"
        type: max
      - name: number
        title: 执收数量
        description: fnumber 合计——跨计量单位混总无意义，按 units 分组时才可加（初步设计 §八.9）
        sql: "{CUBE}.`fnumber`"
        type: sum

    dimensions:
```

### 5.2 fiscal_collection 行级权限（access_policy）

```yaml
# 行级权限：三条款骨架与五要素语义见 §3.2（group/conditions/member_level/member_masking/row_level），
# JWT 占位符与 claims 约定见 §3.1，白名单制硬语义见 §3.2（未命中任何策略=整表拒绝 1=0）。
# collection 差异点：① 财政用户区划过滤落 rec_rgn_code（收入归属区划=财政口径），不是执收区划；
# ② payer_name 脱敏（excludes+masking 同条策略）；③ rec_rgn_code 空值行丢行已核（初步设计 §9.2 #16）。
# 完整 YAML 为落地蓝本（daybook/cbill 同款，docs/11、03-行级权限记录）：
    access_policy:
      # ① 财政用户：JWT 带 region_code → 收入归属区划=本区划
      - group: "*"
        conditions:
          - if: "{ securityContext.region_code }"
        member_level:
          excludes: [payer_name]
        member_masking:
          includes: [payer_name]
        row_level:
          filters:
            - member: rec_rgn_code
              operator: equals
              values: ["{ securityContext.region_code }"]
      # ② 单位用户：JWT 带 agency_code → 执收单位=本单位（场景 13）
      - group: "*"
        conditions:
          - if: "{ securityContext.agency_code }"
        member_level:
          excludes: [payer_name]
        member_masking:
          includes: [payer_name]
        row_level:
          filters:
            - member: chg_agency_code
              operator: equals
              values: ["{ securityContext.agency_code }"]
      # ③ 平台/管理用户：region、agency 均无 → 全量放行（两条 conditions AND）
      - group: "*"
        conditions:
          - if: "{ not securityContext.region_code }"
          - if: "{ not securityContext.agency_code }"
        member_level:
          excludes: [payer_name]
        member_masking:
          includes: [payer_name]
        row_level:
          allow_all: true
```

```yaml
          - count
          - bill_count
          - amt
          - total_amt
          - trans_no

          - sub_name
          - sub_level
          - sub_level_name
          - status
          - enter_status
          - reconcile_status
          - share_rate
          - chg_rgn_code
          - rec_rgn_code
          - pay_acct_name
          - rec_acct_name
          - build_date
          - enter_date
          - reconcile_date

          - fid             # 技术键——view 不继承 public:false，显式挡
```
