## 一、结论先行

三个 cube 的**骨架**对得上查询库报表主干（缴款全景/清分流向/缴库入库），但报表 SQL 里的固定处理逻辑——本文归纳为**"减法"**（先踢掉某些行再统计）与**"加法"**（额外补进来的口径与指标）——**均未落进模型**，直接后果是模型算出的金额与报表对不上；另有票据/汇缴两个已同步未建模的域、生产库九张报表的范围决策。

## 三、报表"减法"——先踢掉某些行再统计

### 3.1 排除线下退付（影响所有缴款类报表金额）

**是什么**：发生过退付（钱退回给缴款人）的缴款书会登记在 `une_paybook_paycode` 表里。报表统计收入时第一步统一排除：

```sql
fpaycode not in (select fpaycode from une_paybook_paycode)
```

出现在 2.2 / 2.3 / 2.4 / 2.6 / 2.7 / 2.10 / 2.11 等全部缴款类报表的 WHERE 首行，目的是避免把已退回的钱还算作收入。

**缺口**：CK 未同步 une_paybook_paycode；fiscal_collection 主 sql 也没有该过滤。当前模型算出的金额是"没减过"的，**偏大**。P0 第一嫌疑。

**落地建议**：同步该表 → collection 主 sql 追加排除（`NOT IN` 子查询不受 CK 23.3.15"每层仅 1 join"限制约束，可在现有 5 层嵌套外或内层追加）。

### 3.2 不明资金分流（到账时间轴分叉）

**是什么**：银行收到一笔钱但认不出是谁缴的（没带缴款书信息），先记入"不明资金"（`fne_unknown_capital` 主表 + `fne_unknown_capital_balance` 余额明细），之后人工认领到某张缴款书。这类缴款与普通缴款**用的字段不同**：普通缴款到账看 `fenterdate`，不明资金认领的到账看 `freceiveddate`。

**报表写法**：全部是双 UNION 分支拼接——普通缴款一个分支、不明资金认领的缴款（`fpaycode in (select fpaycode from fne_unknown_capital_balance ...)`）一个分支，各自用各自的时间列、状态列与过滤条件。

**缺口**：CK 未同步两表；fiscal_collection 只有单一时间轴，没做分叉，按到账日查时两类数据会混着漏。附带影响：到账判定第四条件 `ub.fbalancedate <> ''`（§4.2）同样依赖此表。

**落地建议**：同步两表 → 二选一：① collection 主 sql 内做 UNION 分流（列多、嵌套深，受 CK join 限制，改造重）；② 建独立不明资金 cube，问数层按 paycode 关联兜底。倾向 ②，待拍板。

## 四、报表"加法"——额外补的口径与指标

### 4.1 金额口径 `ifnull(fimamt, famt)`

**是什么**：缴款书票面明细金额是 `famt`；清分/分成后这笔钱实际归属的金额是 `fimamt`。报表统一取：

```sql
ifnull(fimamt, famt)   -- 有分入金额用分入金额，还没清分的用票面金额
```

2.2 / 2.6 / 2.10 等全部金额列如此。

**缺口**：模型 `amt` 只 sum(famt)，与报表永远差一层。

**落地**：collection 补衍生度量（如 `net_amt`），`sql: ifNull({CUBE}.`fimamt`, {CUBE}.`famt`)`，与报表对数验证。

### 4.2 负数退付计入"已完成"

**是什么**：`famt < 0` 的行是退付冲账单。报表把它们直接视为已完成——已到账、已划转的判定条件都带 `or famt<0` 分支（2.6：`case when fp.famt<0 or fp.stats='9' or ub.fbalancedate<>'' then '1' ...`），金额照加（负数自然冲减总额）。

**缺口**：模型 `entered_amt`（freceiveddate 非空单条件）没有该分支，退付单被漏算。完整报表口径是四条件：`fisenter='1' or famt<0 or fstats='9' or ub.fbalancedate<>''`——其中 **fstats/fstats_last 列宽表没有**（26-CK宽表结构 全 129 列无此列），`ub.fbalancedate` 依赖不明资金表。

**落地**：cube 内先补 `famt<0` 分支（衍生维度或度量说明）；fstats 列推进 ETL 补列；fbalancedate 随不明资金域解决。

### 4.3 多时间轴（缺划转、开票两条）

**是什么**：一笔缴款在流程上有多个日期，每个都是报表的独立查询条件：

| 日期 | 字段（宽表） | 报表条件名 | 模型现状 |
|---|---|---|---|
| 缴款日期 | fdate | 缴款日期（2.6/2.10 等） | ✅ pay_date |
| 划转日期 | ftransdate / ftransdate_last | 划转日期（2.6/2.7/2.8/2.10/2.11/2.12） | ❌ 未建 |
| 到账日期 | fenterdate、freceiveddate | 到账日期 | ✅ enter_date / received_date |
| 开票日期 | ffilldate | 开票日期（2.7/2.11） | ❌ 未建 |
| 清分日期 | fcleardate | — | ✅ clear_date |
| 有效期 | feffdate | — | ✅ eff_date |

**缺口**：缺 trans_date、fill_date 两条——"按划转日期查上月划转明细""按开票日期查明细"类问题答不了。列都在宽表，纯建模动作。

### 4.4 缴库三态（未缴库/缴库在途/缴库到账）

**是什么**：专户里的钱最后要缴入国库。缴款明细关联缴库单后分三态（2.3/2.4 的 showstatus 列）：

```sql
case when fttn.ftransdate != '' then '缴库到账'
     when fttn.ftransno != ''   then '缴库在途'
     else '未缴库' end
```

- 没生成缴库单 → **未缴库**
- 有缴库单号但国库未扣款（ftransno 有值、ftransdate 空）→ **缴库在途**
- 国库已扣款（ftransdate 有值）→ **缴库到账**

关联键：缴款书侧 `ftreasuryno` = 缴库单侧 `ftransno`。

**缺口**：宽表 129 列有 ftreasuryno（ETL 补充）但 collection 未建维度；collection↔treasury 无 cube joins。**"未缴库金额还有多少"目前答不了**。

**落地**：① collection 补 treasury_no 维度 + "是否已缴库"衍生（fetreasury 空否，单表即可先答未缴库口径）；② 完整三态需跨表 join（cube joins，注意 CK 23.3.15 限制与 multi-fact 约定），或问数层双查合并。待拍板。
