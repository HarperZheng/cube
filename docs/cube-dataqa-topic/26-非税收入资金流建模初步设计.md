## 一、业务链路 ↔ CK宽表

**记号**：fph=`fne_paybook_high`、fpf=`fne_paybook_full_high`、fdt=`fne_funddivide_transfer`、ftm=`fne_treasury_transfer_main`、uph=`une_paybook_high`、ucb=`une_cbill_high`

| 业务链路 | CK 宽表 | 业务定位 | 关键实证 | 行数 |
|---|---|---|---|---|
| **缴款通知书流** | fpf | 缴款依据 + 缴款 + 代收 + **收入归属**(frec*) + 划拨状态(_last) | 每笔缴款最全宽表（129 列 = fph 的 86 + 43 生命周期列） | 1,272 |
| **清分划拨流** | fdt | ③清分归属 + ④汇总 + ⑤划拨 | **唯一带 from→to 双侧字段**（执收侧 fchg* / 收入侧 frec* / 划拨侧 ftransrec*） | 728 |
| **汇缴通知书流** | uph | 汇缴的划款指令 + 收款确认(fconfirm*) + 缴款计划(fpayplan*) | **无任何归属列**——无 frecrgn/frecsub/fimamt/ftransrec | 9,012 |
| **缴库流** | ftm | ⑥资金进入国库 | 生产 FNE_TREASURY_TRANSFER 68 行（2026-10-09 核实项 6），CK 未同步 | **0 行（等 ETL 同步）** |
| **票据流（并行）** | ucb | 电子票据 + 冲红关联(fwriteoffbill*) | 桥：`fpaycode` | 53,386 |

**关键实证**：**收入归属口径（收入区划/收入科目/收入金额）只存在于 fpf 和 fdt**——uph 是纯过程流，不带归属列。归属场景只靠 fpf+fdt 两个 cube 不是设计巧合，是数据拓扑本身决定的。

## 三、模型设计：资金模块（2 cube + 2 view）

### 3.1 模型总图

```
fiscal_collection   缴款全景事实 (fpf, 明细粒度: 缴款书×项目行)   ← ⓪①②环节 + 归属列
fiscal_allocation   清分流向事实 (fdt, 清分粒度: 唯一带 from→to)  ← ③④⑤环节
       ↓                     ↓
fiscal_collection_view     fiscal_allocation_view
(财政收入明细+汇总7类)      (划入划出/跨区划流向/收入来源/专户国库)
  [folders: 缴款票面口径 / 收入归属口径 → §4.6]
       └──── 单位用户 = 同两 view + access_policy（不是独立模型）─────┘
```

### 3.2 链路覆盖图

**当前依据场景梳理和ck表梳理，只做到清分**——①及之前是本期建模范围，②及之后是链路完整性记录（缺口性质见 §3.4）。

```
执收单位发起缴款通知书（缴款依据，项目明细在明细表）        fpf ✅ fiscal_collection
        ↓ 缴款（直缴/汇缴两条路，缴款渠道）                  fpf ✅ fiscal_collection
        │   ← 欠缴时：财政催缴                              fpf ✅ 可落（场景图未列的加分项）
银行代收（过渡户/汇缴专户，到账反馈）                         fpf ✅ fiscal_collection
        ↓
① 清分 —— 分给什么区划，按分层比例定中央/省/市/县归属        fdt ✅ fiscal_allocation（分成比例列 ❌）
② 汇总 —— 按单位、科目汇总，形成待划拨批次                  fdt ⚠️ 汇总单本身在 CK 没有表，只有 fcollectid 标识
③ 划拨 —— 资金拨付指令与银行划转（可能多轮）                fdt ⚠️ 只留最近一轮 _last
④ 缴库 —— 资金进入国库                                      ftm ❌ 0 行 Blocked
⑤ 对账（国库）、财政记账                                    无表 ❌ 业务文档自认数据空缺
∥ 票据流 —— 电子票据随缴款开具，作废/冲红                   ucb ⚠️ 不并入——票据场景和要素未梳理（见 3.5）
```

### 3.4 覆盖结论（分两个口径回答）

**按场景图的口径（收入归属：钱是谁的、从哪来、分给谁、专户还是国库）——2 cube + 2 view 够。**
16 条场景 14 条 ✅ 可落。这不是设计巧合：归属口径物理上只存在于 fpf+fdt 两条流，uph 是过程流、ucb 是票据流，场景图都没问。

**按业务全链路的口径（缴款书→缴款→代收→清分→汇总→划拨→缴库→对账记账）——不够，而且模型补不了：**

| 链路缺口 | 性质 | 处理 |
|---|---|---|
| ④汇总批次单据/状态、⑤划拨多轮流转+银行报文 | **数据缺**——ETL 打平折叠，只留最近一轮（`_last`）；实测 `fcollectpid` 全 0，多轮归并未发生（核实项 12） | 挂未建模清单；要补需 ETL 加列或 Oracle 侧建 FNE_COLLECT_TO_TRANSFER/FNE_CAPITAL_TRANSFER cube |
| ⑥缴库 | **等 ETL 同步**——生产 FNE_TREASURY_TRANSFER 68 行（非 0），CK 未同步（2026-10-09 核实项 6） | 等 ETL 同步（P4 空表模式不变：不建，同步后再补）；短期 `fbgtstyle`/`ftreasuryno` 代理 |
| ⑦对账/财政记账 | **数据缺**——业务文档自认无表 | 问数命中时按"数据空缺"应答（业务文档 §六.5 原则，参考 18-未建模清单） |

**一句话：缺的段全是"数据本身缺"，不是"模型设计缺"。** 2 cube + 2 view 已把 CK 里存在的资金流口径全部接住；尾段扩展路径见 §9.3。

### 3.5 票据模块为何不在本期

业务篇"三、四"把业务分**资金**和**票据**两个模块，本文档本期只建资金模块（2 cube + 2 view）；**票据模块不建，因为票据的场景和要素未梳理**——场景图只覆盖资金流，票据要哪些场景（资金-票据联查/票据台账/作废冲红统计）、哪些要素还没讨论过。

- 数据侧已就绪：ucb 在 CK（53,386 行），Oracle 侧 cbill 体系已有，join 桥 `fpaycode` 已明确
- 场景与要素梳理完成后建 `fiscal_bill`（§9.3，前置=票据场景与要素梳理）
- 本期涉及票据的口径只有作废/冲红（§八.11 过滤规则），不依赖事实表

## 四、维度设计：码名对注册 + 全量别名归一化

### 4.1 分层总图（物理列 / 虚拟新列 / 成员）

```
CK 宽表（物理表，fpf 129 列）
  ├─ 编码列 fchgagencode / fitemcode / fsubcode …    本来就有 → 直接当分组键
  ├─ 名称原值 fchgagenname / fitemname / fsubname …  一码多名，group by 会裂组
  └─ (仅新增) *_name_canon                            虚拟表 SQL 造的归一化列（全部别名拼接）
                        ↓
cube 成员注册（成员 ≠ 物理列，一条成员一段 sql）
  ├─ 码名对：6 个实体，见 4.2
  ├─ 其他维度：按类别，见 4.3
  └─ 金额列是度量不是维度（4.3 末行）
```

**一句话**：物理上只新增 `*_name` 归一化列（每个归一化实体一列）；`*_code` 和其余维度都是宽表现有列的注册，码名对只是"编码怎么分组、名称怎么展示"的成对注册模式。

### 4.2 码名对：编码怎么分组、名称怎么展示

**码名对 = 同一实体的 code 成员 + name 成员成对注册**：code 管分组（数字准、不裂组），name 管展示（跟随 code、可读）；一码多名环境下只有成对注册才既分对组又看得懂。

每个"分组+展示"实体注册一对成员——**分组必须用 `*_code`（数字准），`*_name` 仅跟随展示（不裂组）**：

| 实体 | code 成员（分组键） | name 成员（默认展示名） | 宽表列 | 名称来源 |
|---|---|---|---|---|
| 执收单位 | `chg_agency_code` | `chg_agency_name` | `fchgagencode` / `fchgagenname` | 归一化（全部别名拼接） |
| 收入区划 | `rec_rgn_code` | `rec_rgn_name` | `frecrgncode` / `frecrgnname` | 归一化（全部别名拼接） |
| 项目 | `item_code` | `item_name` | `fitemcode` / `fitemname` | 归一化（全部别名拼接） |
| 科目·缴款侧 | `sub_code` | `sub_name` | `fsubcode` / `fsubname` | 归一化（全部别名拼接） |
| 科目·收入侧 | `rec_sub_code` | `rec_sub_name` | `frecsubcode` / `frecsubname` | 归一化（全部别名拼接） |
| 执收区划 | `chg_rgn_code` | `chg_rgn_name` | `fchgrgncode` / `fchgrgnname` | **原值不归一化**（名称列是 ETL 补充、fdt 缺；2026-10-09 拍板） |

### 4.3 维度分类总表（类别 + 注册方式 + 具体示例）

| 类别 | 注册方式 | 具体示例 |
|---|---|---|
| **码名对实体** | code+name 成对 | 4.2 的 6 个实体（5 个归一化 + 执收区划原值） |
| **缴收分侧实体** | 成员名带侧别前缀 + view 分 folder | 科目 `sub_*`/`rec_sub_*`、资金性质、区划、预算单位、银行——缴款侧无前缀、收入侧 `rec_` 前缀；description 写明口径差异，ai_context 写明**不可跨侧混用** |
| **普通维度** | 单成员直取 | 业务类型 `fbustype`、资金性质 `ffundsnature*`、收入类别 `fincomesort*`、代理单位 `faccagen*`、预算单位 `frecbgtagen*`、计量单位 `funits`、票据状态 `fstate` |
| **时间维度** | String→date 转换后注册 | `fdate` → `toDateOrNull(fdate)`（§8.5 全 String；time_shift 同期对比靠它） |
| **无名称实体**（只 code） | 单成员 `*_code`（title 写"收入单位编码"），description 明示"名称列缺口，待 ETL 补" | 收入单位 `frecagenidcode`、主管部门/归口处室（实测 fdeptid/fbusinessorgcode 全 0，**仅 `fchgfindeptid` 财政处室 99% 可用**，2026-10-09 核实项 13/14）——**不造名字、不拿别的列冒充** |
| **敏感字段** | 建维度 + mask 脱敏（`member_level: excludes` + `member_masking: includes` 同条策略，P3 语义） | `fpayername`（缴款人名称）建+脱敏；`fpayerno`(账号)/`fpayerid` 不建维度 |
| **技术键** | 可建但 `public: false` | `fpid`/`fid`/`fpaybooksubid`/`fdatatag`；view `includes: "*"` 时显式 excludes（docs/07 规则） |
| **不是维度 → 度量** | measure 分口径注册 | `famt`(执收明细)/`fimamt`(清分收入)/`ftransamt`(划拨)；`ftotalamt` 禁 sum（fan trap）；`fnumber` 须按 `funits` 分组才可 sum |

**"缴收分侧"是什么**：同一业务概念在资金流上的**两个时点**——缴款票面（缴款发生时票面上申报的，无前缀成员，回答"按什么交的"）vs 收入归属（清分/分成后资金实际归属的，`rec_` 前缀成员，回答"最终归谁"）。清分会改归属，票面值≠归属值、两套都要留；同一笔钱两侧各有一个值，跨侧分组/相加=重复计算，不可混用（§2.3 收入类型行即靠两套比对衍生：`fchgrgn=frecrgn`→正常收入）。

侧别写法（title 带侧别字样，AI/人工选成员时与问题关键词直接对上）：

```
sub_code      title: 预算科目（缴款票面）  description: 缴款书票面申报的科目口径
rec_sub_code  title: 预算科目（收入归属）  description: 清分/分成后资金实际归属的科目口径
```

### 4.4 归一化实现（全量别名拼接）

**归一化的必要性**：一码多名下（CK fpf 实测 36 个编码 / 48 个编码-名称对 = **12 个编码多名**，如 125026 = 开票点一×42 / 李思维×34 / 云南医保测试单位改名×11），`group by (code, 名称原值)` 会裂组。解法：cube 的 sql 虚拟表里 LEFT JOIN 预聚合子查询，让同一编码的所有行共享同一串"全部别名"：

```yaml
cubes:
  - name: fiscal_collection
    sql: |
      SELECT t.*, c.chg_agency_name_canon, r.rec_rgn_name_canon,
             i.item_name_canon, s.sub_name_canon
      FROM fne_paybook_full_high t
      LEFT JOIN (SELECT fchgagencode,
                        arrayStringConcat(arraySort(groupUniqArray(fchgagenname)), ' / ') AS chg_agency_name_canon
                 FROM fne_paybook_full_high GROUP BY fchgagencode) c USING (fchgagencode)
      LEFT JOIN (SELECT frecrgncode,
                        arrayStringConcat(arraySort(groupUniqArray(frecrgnname)), ' / ') AS rec_rgn_name_canon
                 FROM fne_paybook_full_high WHERE frecrgncode != '' GROUP BY frecrgncode) r USING (frecrgncode)
      -- fitemname/fsubname 同式各一条 JOIN（别名 i.item_name_canon / s.sub_name_canon）
    dimensions:
      - name: chg_agency_code
        sql: fchgagencode
        title: 执收单位编码
      - name: chg_agency_name
        sql: chg_agency_name_canon
        title: 执收单位名称            # ← 用户看的"名称"=全部别名拼接
```

- **"最新=正确"已否决**（核实项 10，2026-10-09）：抽 124994/125026/425103 看名称时间序列，0/3 支持——124994 同月/同日多名混用（非改名序列）、125026 最新名为人名"李思维"（脏数据）、425103 最新名为单日变体。定性**测试环境脏数据**：不赌规范名、不挑名，**全部别名都展示**（§9.1 #7 拍板）
- 拼接**字典序**（`arraySort`）、分隔符 `' / '`，确定可复现；单名编码拼接后 = 原名，无副作用
- **不加"主名"成员**（2026-10-09 拍板）：一种口径一份展示；**ETL 名称主数据撤下**（测试脏数据不投入根治；核实项 7 只保留补缺列——region 层级、收入单位名称、主管部门名称）
- **实现用 LEFT JOIN 预聚合，不用窗口函数**：`groupUniqArray` 等 DISTINCT 聚合在 CK 23.3 窗口里报 NOT_AN_AGGREGATE（实测），原 argMax OVER 方案整体废弃
- `fdatatag` **全表 1,272 行全空**（2026-10-09 实测）→ 归一化不再按它分区；将来分环境需要时子查询 group by 补列（核实项 5 CK 侧结论）
- 归一化后 `(code, name)` 函数依赖成立 → 分组带名称**不裂组**
- 行级名称原值仍在宽表（sql `SELECT t.*`），不预置 snapshot 成员——行级对账需要"当时名"时再补注册（2026-10-08 拍板弃 `*_name_snapshot`）
- 明细 1,272 行 JOIN 开销可忽略；未来数据量大再物化
- CK 侧无 Oracle 11g 30 字符标识符上限（P3 的 ORA-00972 坑不适用），成员名可用完整驼峰

## 八、口径与数据质量清单（建模时写进 ai_context / description）

1. **一码多名（测试脏数据，核实项 10 已定性）**：分组键一律用 code/idcode；`*_name` = 全部别名字典序拼接（`' / '`），不赌规范名、名称列不作准——CK 侧 12 个编码多名（36 编码/48 对，如 125026 = 开票点一 / 李思维 / 云南医保测试单位改名）
2. **CK ≠ Oracle 口径**：CK 是跨环境聚合库（une_cbill_high 53,386 vs Oracle 6,772），行数不可对账；`fdatatag` 列疑似环境标签——核实其取值，决定口径是否分环境过滤（核实项 5）
3. **treasury CK 0 行 = 等 ETL 同步**（2026-10-09 核实）：生产 FNE_TREASURY_TRANSFER 68 行（fsublevel 68/68 填充）、FNE_TREASURY_TRANSFER_ITEM 74 行（fsharerate 100% 填充）——缴库主题从"真缺口"改"等同步"，CK 真缺列只剩 `fcalcsource`
4. **测试数据主导**：yn0411 实测几乎全是测试单位（测试云南测试环境、开票点001、智能核销*），真实业务行极少——同期对比等场景出数难看，预期管理
5. **全 String 类型**：日期列全部 `String`，time 维度需 CK 转换（`parseDateTimeBestEffort`/`toDateOrNull`）；金额是 `Nullable(Decimal(18,6))` 可直接 sum
6. **拼写原样**：`ftrnasreconciledate` 拼写错误原样保留，不修正
7. **`_last` = 最近一轮**：一笔清分多轮划拨只留最新轮，历史轮次不可查
8. **`ftotalamt` 明细粒度重复**：整票金额复印在每明细行上，禁 sum（fan trap）
9. **`fnumber` 跨计量单位混总无意义**：按 `funits` 分组时才可 sum
10. **缴款人口径**：fpf 缴款人=外部单位或个人（直缴票面）；uph 汇缴通知书缴款人=单位自己——两表不能混用（业务篇 §六.1）
11. **作废/冲红口径**：作废票不计收入（fstate 过滤）；红字负数冲减通常入账在下一会计期间，按期间统计注意归属期（业务篇 §六.6）
