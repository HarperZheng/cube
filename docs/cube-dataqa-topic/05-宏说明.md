# 05 宏说明：conf/model/macros/ptd.jinja

> 用途一句话：**一个度量自动生成 4 个"累计"指标**——它是一个"复制模板机器"：
> 你给它一个基础度量，它吐出周累计、月累计、季累计、年累计 4 个度量定义，
> 不用手写 4 遍。
> 来源：docs/12 §5 官方 recipe，P3 实测通过（实测细节见 [04-P3-记录.md](./04-P3-记录.md) §5）。

## 不用宏（手写）

```yaml
# 想要金额的年累计？手写一遍
- name: amt_year_to_date
  sql: '{CUBE}."FTOTALAMT"'
  type: sum
  rolling_window:
    type: to_date
    granularity: year
# 月累计？再抄一遍，只改两处...
- name: amt_month_to_date
  ...
```

2 个度量 × 4 周期 = 手写 8 个，而且加一个周期（比如周累计改成旬）要改所有文件。

## 用宏（实际写法，cbill.yml 里就两行）

```jinja
{%- import 'macros/ptd.jinja' as ptd -%}          ← 引入模板机器
...
{{ ptd.to_date_measures("amt", '{CUBE}."FTOTALAMT"', title='金额累计') }}
```

## 这一行在编译期展开成

```yaml
- name: amt_week_to_date        # 周累计
  sql: '{CUBE}."FTOTALAMT"'
  type: sum
  title: 金额累计(week)
  rolling_window: { type: to_date, granularity: week }
- name: amt_month_to_date       # 月累计
  ...（同上，granularity: month）
- name: amt_quarter_to_date     # 季累计
- name: amt_year_to_date        # 年累计
```

## 直观类比

| 类比 | 对应 |
|---|---|
| 表格公式拖拽填充（Excel 拖出 4 列） | 宏按 `periods` 列表循环生成 |
| 改模板一处、4 个结果一起变 | 加个周期只改宏的 `periods` 默认列表 |

## 两个要点

- 它在**编译期**展开——YAML 还没被 Cube 解析时就已经变成 4 个度量定义了，
  Cube 本身不知道宏的存在；
- 它**不减少成员数**——省掉的是源码里的重复，模型里该 4 个成员还是 4 个。

## 参数说明（相对 docs/12 原文的增强）

`to_date_measures(name, sql='', type='sum', periods=[...], title='')`：

| 参数 | 说明 |
|---|---|
| `name` | 度量名前缀，生成 `<name>_<period>_to_date`。**注意 11g 30 字符上限**：cube 前缀+成员名超 30 字符报 ORA-00972，用短名（如 `amt` 而非 `total_amount`） |
| `sql` | 基础度量的 SQL（如 `'{CUBE}."FTOTALAMT"'`，作为 Jinja 字符串参数安全）；不传则生成度量无 sql（count 型保持 COUNT(*)） |
| `type` | 度量类型，默认 `sum` |
| `periods` | 周期列表，默认 `['week', 'month', 'quarter', 'year']`，可传子集避免生成没人用的成员 |
| `title` | 中文标题（P3 增强，docs/12 原文无此参数），生成 `标题(period)`，如 `金额累计(week)` |

## 使用约定（02 约定第 7 条）

- 时间口径度量（to_date 系列等"一个度量 × N 周期"形状）用宏批量生成；
- 成员定义复用（多表同口径）走 `extends`——两者分工：宏管"形状复制"，
  extends 管"定义引用"；
- 按 to_date 窗口自身粒度分组时窗口值=基础度量（按月分组看月累计就只是当月值），
  要看累加效果按更细粒度分组（docs/12 §5 末尾）。
